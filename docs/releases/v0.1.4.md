# kist v0.1.4

Faster large-file uploads, clearer search conditions and operation history, and
a more consistent interface for browsing and managing personal archives.

## Changes

- Stream upload hashing in a browser worker and verify blocks as they arrive on
  the server. Show upload-stage timing and a compact completion summary.
- Resolve same-name uploads by replacing existing files or keeping both copies.
  Replacement preserves history and supports strict undo. Improve drag-and-drop
  and clipboard upload confirmation.
- Rename files and folders inline, and move individual entries or directory
  contents to the recycle bin through shared row and context menus. Add file
  type and size sorting and correct file/folder completion counts.
- Edit searches as separate keyword and field/operator/value conditions. Keep
  searches inside the current directory and its descendants when browsing a
  directory. Existing saved searches remain readable.
- Add searchable box and tag selectors with a separate search field. Distinguish
  scope and placeholder options; show optional box start dates to disambiguate
  names. Selecting a tag adds it immediately; remove tags from their context menu.
- Add a calendar picker supporting year, month and day precision, including a
  Today shortcut. Refine box editing dialogs and date guidance.
- Show object names and change summaries in operation history. Compact history,
  recycle-bin, restore and version-comparison views, with readable timestamps.
- Group file metadata by source, translate known fields and format modification
  timestamps. Pointer-following tooltips expose original keys and timestamps.
  File details start closed and remember the user's choice across refreshes.
- Unify page headings, toolbar buttons, navigation/download buttons, list/grid
  alignment, context menus and dialog transitions. Refine tag shapes and search
  tokens; avoid automatically highlighting the gallery's Back button.

## Upgrade

Existing v0.1.x libraries can be opened directly. This release introduces no
destructive migration and does not require reinitializing the library. Stop all
writers before upgrading and refresh browser pages afterward. Keep normal
scheduled backups; a new full-library backup or blob scrub is not required for
this compatible forward upgrade.

This release adds `upload_files`, `undo_upload_files`, `rename_entry`,
`delete_entry_contents` and `restore_entry_contents` journal actions, and version
2 saved-search definitions. Older binaries do not understand these new records.
After using the corresponding features, keep v0.1.4 or newer. To support an
older-version rollback, create a pre-upgrade recovery point and restore that
matching library rather than only replacing the executable.

Pull `jinzhao1994/kist:v0.1.4` or `ghcr.io/jinzhao1994/kist:v0.1.4` and recreate
the container, preserving the library mount, UID/GID, ports and trusted origins.
Binary assets, versioned container images and `latest` promotion finish
separately; use each registry's tag after its verification workflow succeeds.

Native packages cover Linux x86-64, macOS Intel/Apple Silicon and Windows x86-64.
Verify downloads against `SHA256SUMS`. Images support Linux amd64 and arm64.

## Limits

There is no built-in login; use a trusted network or an authenticated reverse
proxy. Original files and journals are retained permanently, so deletion does
not reclaim disk space. Unsupported media remain downloadable. Browser upload
recovery still requires the same browser profile/site and reselecting the
original files; mobile background uploading is not guaranteed.
