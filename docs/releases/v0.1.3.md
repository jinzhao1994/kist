# kist v0.1.3

Resume interrupted uploads with end-to-end verification, save reusable searches
in your library, and browse folders and files in a more compact interface.

## Changes

- Add resumable uploads with pause/resume, recovery after browser refresh or
  server restart, per-block SHA-256 checks, whole-file verification, and final
  blob verification before an all-or-nothing batch commit. After reopening a
  page, reselect the original batch to verify its identity and send only the
  missing data. Completed receipts can be checked without the original files.
- Raise the default upload limit to 32 GiB and 1,000 files per batch. Limits
  remain configurable. Hashing runs incrementally in a browser worker.
- Add library-backed saved searches under Favorites, including rename, update,
  deletion, operation history, rebuild and strict undo support.
- Add typed search-condition suggestions, including box and tag filters, and
  preserve search conditions when returning from the gallery.
- Add nested directory browsing, creation and uploads inside boxes. Folders and
  files share one list or grid, with folders first. Compact file rows use icons,
  extension-based types and modification time by default. Content time is named
  accurately because it may come from source-file modification time, not EXIF.
- Refine box lists with sortable headings, compact rows, start-date display and
  an end-date tooltip. Consolidate view controls and less frequent actions into
  menus; move upload, directory and tag actions into the box's add menu.
- Add tag context menus and inline rename. Menus open at the pointer, use smaller
  text and highlight the active tag. Improve tag selectors, sidebar labels and
  navigation alignment; move display settings beside the version.
- Publish stable images to Docker Hub as well as GHCR. Stop publishing the
  development `edge` channel; version tags and `latest` remain available.

## Upgrade

Existing v0.1.x libraries can be opened directly. This release adds a saved-search
index table and a file modification-time index through automatic, non-destructive
SQLite migrations. Original files, journals and library configuration remain
compatible with forward upgrades. Do not initialize an existing library again.

New `create_saved_search`, `update_saved_search` and `delete_saved_search` journal
actions are not understood by older binaries. After using Favorites, keep
v0.1.3 or newer. Returning to an older binary requires restoring its matching
pre-upgrade library recovery point, not just replacing the executable. Older
versions may also reject a database migrated by this release.

Stop all writers before upgrading and refresh browser pages afterward. Old
upload pages without checksum support must be refreshed. No fresh full-library
backup or full blob scan is required for this compatible upgrade; keep scheduled
backups independently, and create a recovery point if older-version rollback is
needed. Preserve the library mount, UID/GID, ports and trusted origins.

Pull `jinzhao1994/kist:v0.1.3` or `ghcr.io/jinzhao1994/kist:v0.1.3` and recreate
the container. To follow stable releases, refresh `latest` after that registry's
verification workflow succeeds. Binary assets, versioned images and `latest`
promotion complete separately. Existing `edge` tags are no longer updated.

Native packages cover Linux x86-64, macOS Intel/Apple Silicon and Windows x86-64;
verify downloads against `SHA256SUMS`. Images support Linux amd64 and arm64.

## Limits

Resumable sessions use discardable `uploads/` staging in the library volume and
expire after seven idle days. Reserve space for both staging and final blobs.
Browser recovery requires the same browser profile and site address; continuous
background uploading on mobile is not guaranteed. The 32 GiB default is a
configuration limit, not a claim of real-device testing at that size.

There is no built-in login. Use a trusted network or an authenticated reverse
proxy. Original files and journals are retained permanently; deletion does not
reclaim disk space. Unsupported media remain downloadable.
