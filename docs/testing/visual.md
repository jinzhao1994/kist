# Visual regression checks

`Visual` builds both the last approved commit and the current commit, serves each against its own isolated empty library, and captures deterministic UI fixtures in the same pinned Linux amd64 Playwright image. Each revision uses its own application, dependency lockfile and test scenarios; both use the current capture driver and browser settings. API responses and preview artwork are synthetic; this is a visual check, not a substitute for backend or media integration tests.

The suite covers every built-in theme in light/dark mode, boxes, box files/upload controls, settings, tags, an empty library, English, a mobile grid, six media detail states, operation history/details, the recycle bin, historical boxes, and file version comparison. Fixtures use fixed dates, locale, timezone and preview artwork. No personal archive is accessed.

## Review a change

1. Open the failed **Visual** run in GitHub Actions.
2. Read its summary. Download `visual-report-<attempt>`, extract it, and open `report/index.html`. Compare expected/current/diff images. Click an image for full size. Capture failures include Playwright traces under `test-results/` and cannot be accepted.
3. If every change is intentional, run **Accept visual baselines** on `main`, entering the reviewed Visual **run ID**. The equivalent CLI command is:

   ```sh
   gh workflow run visual-accept.yml --ref main -f run_id=RUN_ID
   ```

4. The workflow downloads the candidate, validates its provenance and completeness, updates only the approved commit reference in `web/visual/baseline.json`, and pushes normally. It explicitly dispatches **CI** and **Visual** after the bot push. Confirm both pass on the new commit.
5. Fast-forward your local branch before continuing development:

   ```sh
   git pull --ff-only
   ```

If the source run is stale, rerun Visual on current main and review that run instead. If validation or capture failed, fix the cause; do not accept a partial suite. If the bot pushed but dispatch failed, manually run CI and Visual on main. Branch protection may require an approved repository workflow change; this workflow never bypasses it or force-pushes.

Only `web/visual/baseline.json` is tracked for baseline storage: the full approved commit SHA, capture-environment fingerprint, and reviewed run ID. Baseline/current/diff PNGs are generated during CI and stored in artifacts. Candidates expire after 14 days; reports and traces after 30 days. Expired artifacts can be regenerated by rerunning Visual; acceptance still requires a reviewed run on current main.

Direct pushes to main do **not** advance this reference. A passing comparison also leaves it unchanged. Pull requests use the reference from their base commit, so editing the reference in a PR cannot silently bless that PR. The approved commit must remain an ancestor of the tested revision. Migration starts from the commit behind the previously reviewed PNGs, not the latest main. Previously committed images remain in Git history; this migration does not rewrite history.

## Maintain the suite

Add cases to `web/visual/tests/`. Each test has a unique lowercase hyphenated title and exactly one screenshot. Theme cases derive from the application's theme registry. Unexpected API requests and page errors fail capture. Keep loading/error states explicit and deterministic.

`make check` validates TypeScript and the artifact guards without launching a browser. Visual capture runs in Actions. Update `web/visual/environment.json` together with the exact `@playwright/test` dependency when changing browser versions, then review the new captures. An environment fingerprint change requires explicit acceptance even if both newly generated sets match. Comparison uses pixelmatch's 0.1 color threshold and default antialias filtering, with zero differing pixels allowed after filtering. Missing, removed and resized images fail too.

The acceptance workflow only accepts a completed Visual push/manual run from this repository's current main commit, checks the latest attempt, approved baseline SHA and exact artifact contents, and verifies PNG hashes. Both captures must complete before an acceptable candidate is published. If the approved revision no longer builds or its scenarios cannot run with the current driver, fix the compatibility problem explicitly; there is no fallback that compares the current revision to itself. It never automatically decides that a visual change is correct.
