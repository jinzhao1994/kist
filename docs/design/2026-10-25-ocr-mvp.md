# 本机 ChatGPT 登录与图片 OCR 首版

状态：2026-10-25 用户授权实施基础 OCR，明确选择本机运行与浏览器、本次结果保存到文件 metadata。补充 [讨论备忘](2026-10-25-ai-extraction-discussion.md)，不授权发布。

## 范围

设置页连接 ChatGPT，文件详情手动发起单张图片 OCR，查看和复制持久化结果。支持 JPEG、PNG、静态 WebP；其他格式明确拒绝，后续再接转换。仅本机回环访问可管理连接和发起付费模型请求。最初范围不自动扫描；该限制已由下方用户补充取代，2026-10-26 实现新增自动识别与显式补全。仍不做全文检索、PDF、描述、KV 模板或 NAS 登录。

使用官方 SIWC 动态注册、PKCE、state、nonce 和 OIDC 验签，不复用 Codex 凭据。令牌保存在本实例 kist.toml 私有配置中，不进入日志和数据同步；配置锁串行化刷新，调用前重新读取。临时授权事务可在进程内保存，十分钟过期，不作为可持久配置缓存。首版单个活动注册，注销尝试远端撤销并清除本地令牌，保留注册身份与 host ID 供重连。

模型来自当前账号的 /v1/models 列表；优先 gpt-6-luna，账号不提供时由用户选择，不静默使用更贵模型。Luna 支持图片，但 OCR 准确率须用样本验证。公开 Responses 接口使用 store=false、stream=true，只有 response.completed 才能保存；中断、拒绝和不完整输出不提交。

## 存储与一致性

OCR 是按需逻辑提取器，不加入上传自动提取注册表；后端适配与提取语义分离。保存 ocr:text、ocr:model、ocr:recipe，source=ocr；模型字段包含服务商前缀，字段简化决定见本文末尾。复用 extract_metadata、逆操作、目标索引和重放路径，不新增 action 或 schema。

文本仍内联 metadata 和日志：单张图片首版设置 OCR 正文最大 256 KiB，超限报错不截断。1024 字节继续保护 EXIF 与其他短字段，不能作为所有文本的通用语义限制。主设计原先依据 EXIF 将长值视为二进制的假设不适用于 OCR；此处仅开放 ocr:text 的 text 值。暂不选择 blob 引用，因为当前单图范围可保持既有模型；未来多页长文本再根据实测评估日志体积与按需读取。上限是资源保护，不是识别完整性的承诺。

首次成功后不自动重跑；切换模型不改变既有结果。用户删除的墓碑保持保护。调用前固定原文件与 metadata 快照，提交在写锁下检查输入 blob、提取版本和原 metadata，避免覆盖期间产生的过期结果。模型调用不持资料库写锁。rebuild、snapshot 与 verify 不请求网络，离线端可重放既有 OCR 结果；首版只在主库提供 OCR 发起入口。

## 验证

验证 OAuth state/nonce/签名/账号、凭据刷新与退出、SSE 完成判定、输出边界、输入格式、长文本重建与撤销、覆盖冲突、接口本机限制、UI 状态与完整视觉场景。真实登录需用户在浏览器完成；自动测试使用隔离 HTTP 服务，不读取个人凭据。真实验收只发送合成测试图片；日常使用遵循用户保存的自动识别配置或明确的手动／补全请求。

## 用户补充：后台识别、统一模型与代理（2026-10-25）

用户实测后确认：自动 OCR 是可配置项，**仅处理启用后新增的图片**；已有图片保留单张手动入口，并提供“补全已有图片的文字识别”按钮。它只补未完成项，跳过成功及排队/运行中的项，允许明确重试失败项。原先全程逐张手动的范围不能满足日常归档，因此扩展为服务生命周期的后台任务；默认仍关闭，不在升级或登录时自行启用。

模型移到设置页统一选择，手动、自动和查缺补漏共用。模型列表由后端访问提供方，浏览器不持有令牌；明确显示加载、失败重试和空列表。文件侧不再逐次选模型，识别入口与结果、任务状态放在文字识别区，不能混在基本信息中。连接状态与使用说明分开，说明发送到 OpenAI 及使用 ChatGPT 套餐，自动模式标明只处理以后新增的图片。

后台任务状态是可丢弃的本机运行数据，沿用 derived 下 JSON 状态与 OS 锁的做法，不引入新 action 或 schema。成功仍只以日志及提取索引为准；重启不重发已成功的请求，失败/中断不无限自动重试。任务串行执行，模型请求不持资料库写锁，关闭网页不停止服务端任务。提供暂停/继续，已在途任务完成后停止派发。启用自动模式记录当前日志边界，以新增入库操作而非照片拍摄时间判定“以后新增”；历史补全必须显式发起。

用户同时确认代理需求：设置一个 AI 请求代理地址，支持 HTTP 及 SOCKS5，留空继承进程环境代理。作用于后端的授权交换/刷新/撤销、模型列表、OCR 请求；浏览器登录页沿用浏览器自身网络。代理不影响归档同步、地图等无关请求，不记录含凭据的代理地址或认证头。

真实调用已确认登录与模型列表（包括 gpt-6-luna）可用。透明底黑字样张直接发送时曾返回空文字；发送前合成白底后，Luna 已正确识别并通过正常日志写入姓名、编号和日期。只转换请求图片，不修改原始 blob；源文件校验值仍记录原文件身份。流式读取同时支持 delta 与 done-only 文本，不把缺失正文事件的 completed 当作成功。

文件详情的识别入口与文字统一置于元数据的 **OCR** 分组，不在基本信息重复展示。已知字段按界面语言命名，原始 key 继续通过既有提示查看；源文件 SHA-256 使用文件 ID 的省略及完整复制交互。空识别结果明确显示“未识别到文字”，不显示空白文本框和无意义的复制按钮。

识别文字与普通元数据共用字段行，不使用独立文本框或整行复制按钮。展示时将连续换行（包括空白行）合并为一个 `↵ `（标记后一个空格），标记使用较小字号及次要灰色、连续空白折叠为一个空格，最多三行并截断；复制按钮紧随预览的最后一行，仅最后一行为按钮留空间；按实际栏宽截断，文字使用普通字体，复制始终保留完整原文和原始空白。此规则只影响显示，不改动保存的 OCR 元数据。

OCR 提示词属于提供方无关的任务定义，保存在 `internal/ai/prompts/` 文本文件中，由共享 AI 层通过 `go:embed` 随单二进制分发。适配器仅映射到对应 API 的指令／输入字段，不各自维护一份 OCR 提示词。本次只移动存放位置，发送内容与 recipe 版本不变；暂不引入运行时编辑、外部文件路径或模板系统。

## 后台队列实现（2026-10-26）

`ai_options` 保存默认模型、自动开关、启用日志边界及代理；独立 revision 防止设置覆盖，与令牌刷新互不冲突。边界在资料库写锁内取当前日志 head，重新启用不追溯停用期间新增图片。候选从已有 `ops` / `op_files` 导入索引推导，不查询 payload，不新增索引表。`derived/ocr/queue.json` 保存待办、失败与扫描游标，OS worker 锁保证多进程也只有一个识别请求；状态锁只保护短读写，不跨网络调用。

启动发现运行中任务时，先查权威提取结果；已完成的清理，未完成的标为中断并暂停，避免自动重复计费。普通失败也暂停派发；“继续队列”只继续待办，失败项需明确重试。补全失败按钮包含未完成图片及失败项，暂停时需继续队列。排队期间删除、替换或已完成的旧任务在派发前丢弃；调用期间的变更仍由提交快照校验保护。关闭自动模式撤掉尚未派发的自动任务，保留显式手动／补全任务和失败记录。成功结果不依赖队列文件，删除派生状态不会删除文字，但会丢失暂停、失败与待办记录。

本机验收使用同一张合成证件样张的独立文件：启用前导入保持未识别，启用后导入在浏览器关闭时由后台 Luna 完成，随后通过设置页补全旧文件；两者均正确保存 `TEST-2026-001`，`verify --deep` 校验通过。代理用隔离 HTTP 服务验证普通请求转发和 HTTPS CONNECT；未连接用户实际 VPN 或代理服务器。

## HEIC / HEIF 图片输入（2026-10-27）

用户授权将静态 HEIC / HEIF 接入 OCR 与描述的共享输入链路。原首版仅接受 JPEG、PNG、静态 WebP 的限制导致手机原图无法直接使用 AI 功能，现复用预览已有的 libheif 解码、方向变换和分块拼合能力，在后端转换为质量 95 的全分辨率 JPEG。不能直接使用 2048px 预览图，以免丢失文档小字。转换只生成临时输入，完成或失败后清理，不创建第二个归档文件、不修改原始 blob；源文件校验值仍记录 HEIF 原文件。

输入按内容识别，不信任扩展名；前端扩展名只作为基本 metadata 未提取前的入口提示。自动队列、显式补全、单张处理及重新提取共享支持范围，新增格式不改变“只自动处理启用后新增图片”的边界，也不自动重跑成功结果。缺少 libheif 工具、图片序列、多图集合、损坏数据或超限时拒绝调用模型，沿用失败暂停与显式重试。保持原有 20 MiB AI 输入／输出和 6400 万像素上限，解码临时 PNG 另受现有媒体解码字节上限保护。

这次不调整已有 JPEG／PNG／WebP 的提示词或处理版本，不新增 action、schema、派生缓存 recipe 或持久转换副本。成功结果仍走原有提取操作、撤销、重建、同步和提交时输入冲突校验。

## 图片精细度试用（2026-10-27）

用户确认将 OpenAI 的 OCR 与描述共用图片请求从 `detail: high` 改为 `detail: original`，用于比较病历小字的识别效果。此前虽然发送完整分辨率，`high` 的模型侧缩放仍可能损失细节；本次仅调整适配器请求参数，不改提示词、处理版本、原始图片或已有结果。已有图片需显式重新提取。

`original` 仍受模型支持范围和图像预算限制，可能增加消耗，不保证纠正模糊姓名；不静默回退到 `high` 或自动重试，错误沿用既有队列处理。暂不加入裁剪、校正或更换模型，以便单独比较此参数的效果。

## 姓名等字段的逐字辨认试验（2026-10-27）

用户希望评估 Luna 配合提示词改进能否降低使用 Terra／Sol 的成本。试验在 OCR 与描述中增加基于字形逐字辨认姓名、机构名称及编号的要求，强调少见字符组合不能按常见词或上下文替换，核对形近字笔画与部件。OCR 保留可辨部分，仅将不可辨部分标为 `[illegible]`；描述省略无法可靠读出的姓名或编号。未加入正确姓名或特定混淆字对，避免泄漏答案；保留 `original` 与既有推理设置。

本机两种格式各调用一次 OCR 和描述，四项均使用 Luna。相对于此前的结果，本轮两个 OCR 姓名均错误并多识别出一个字；HEIC 描述姓名错误，JPG 描述省略姓名；两个描述还错误识别医院。单份文档、单次采样不足以判断一般准确率或证明提示词导致退化，但没有观察到值得默认启用的改进。因此恢复原提示词，默认模型按用户成本偏好保留 Luna，不自动重跑或覆盖本次结果。

试验结果在本机 metadata 中标为 OCR 处理版本 2、描述处理版本 4；当前正式提示词仍为 OCR 1、描述 3。后续如采用不同的新提示词，应使用 OCR 3／描述 5 或更高版本，避免复用本次试验版本。提取载荷结构版本始终为 1。

本轮新增指令原文（分别追加对应任务的不可辨认规则）：

> Names, organization names, identifiers, and similar fields may contain uncommon characters or unusual combinations. Read them character by character from the visible shapes; do not substitute a more familiar word or spelling based on context. Carefully compare strokes and components of visually similar characters. Do not guess missing or unclear characters.

## Luna 推理强度对比（2026-10-27）

用户授权比较 `low`／`medium`／`high`。隔离工具复用正式客户端、授权刷新与代理，仅替换请求的 `reasoning.effort`；同一份原始 JPG、`original`、OCR 1／描述 3 提示词保持不变，不转正、不分块、不改默认设置或归档 metadata。每档各两次 OCR 和描述，共 12 次；第一轮按 low→medium→high，第二轮反向执行。原图、输出原文和包含原文的结果文件仅保存在本机，不进入 Git 或 CI。

| 强度 | OCR 姓名正确 | 描述姓名 | OCR 平均秒数 | 描述平均秒数 | 每组 OCR＋描述平均输出 token |
| --- | --- | --- | --- | --- | --- |
| low | 0／2 | 2 次正确 | 12.7 | 16.4 | 371.5 |
| medium | 0／2 | 1 次正确，1 次多出字符 | 23.7 | 8.1 | 900.5 |
| high | 2／2 | 1 次明确正确，1 次带不确定措辞 | 31.3 | 20.1 | 1708 |

姓名按完整字段人工核对，不能把“正确姓名是错误长姓名的子串”算作正确。各组医院名称均未准确完整识别；high 的 OCR 仍错误，描述改为省略或声称无法辨认。结果只证明本次样本上 high 的姓名识别有所改善，不代表完整 OCR 准确或一般准确率，也没有测试 HEIC 或更多文档。

每组 OCR＋描述输入为 29187 token，缓存命中为零；输出包含推理 token。OCR 推理 token：low 为 0／0，medium 为 386／675，high 为 1138／941；描述对应为 0／0、0／0、372／218。按当日已核实的 Luna 标准 API 单价（输入 $0.10、输出 $0.50／百万 token）计算，1000 组对应约 $3.10／$3.37／$3.77，high 比 low 约高 22%；这是实测 token 的 API 等价估算，不是 ChatGPT 套餐扣费或额度比例。low 两次描述耗时约 6.6 秒与 26.2 秒，样本量小且有波动，不应据此推断各档固定延迟。

本轮保留原默认 low，尚未实现推理强度配置。后续是否采用 high，需结合更多独立样本和用户对耗时的偏好决定。
