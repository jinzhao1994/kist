# 统一实例设置

状态：用户已授权实现（2026-10-23）。补充权威设计中的配置和离线客户端部分。

## 配置归属

主库与客户端各有自己的 `kist.toml`，不经数据同步互相覆盖。两端提供「设置」页面，控制持久化配置；「显示设置」继续保存浏览器偏好。主题主色迁入实例配置，明暗模式、语言、格式、显示时区仍归浏览器。

原先主库 kist.toml、客户端 client.json / connection.json 及主库 sync-access.json 分散保存，且靠 kist.toml 是否存在识别主库。此方案已不适用：统一为带明确 mode 的配置；旧主库缺少 mode 时视为 library，旧客户端首次打开迁移成 client。同步日志、目录边界、缓存索引和离线保留选择是运行/操作状态，不改成设置项。

## 文件与修改语义

缺省项使用完整默认值；身份在初始化时固定。资料库时区明确初始化，不随设备时区漂移，允许用户通过设置修改。未知键、未知版本、无效值拒绝。实例 ID 与绑定库 ID 不允许通过设置编辑。配置携带凭据，统一以私有权限、原子替换与目录同步保存。读出 API 不包含凭据明文或摘要，替换凭据沿用连接验证流程。

UI 修改通过 library 编排，使用配置内容摘要检测过期编辑，并使用跨进程配置锁串行化程序写入；保存前重新读取，保留未修改项。尽量保留原文件注释与格式；无法安全局部替换的合法 TOML 使用语义等价编码，不静默丢弃未知键。恢复默认意味着删除显式项，而非固化当前默认值。

GPS 与 AI 的设置分区也提供逐字段恢复默认，包含布尔开关，复用普通字段标题行的悬停／键盘聚焦入口。默认值由后端返回，点击只修改草稿；保存时后端按字段名解析恢复意图，不信任客户端传回的默认值。仍保留配置版本检查和自动处理启用边界。GPS 自动查询默认开启、失败后暂停默认开启、间隔默认 2 秒；AI 自动提取默认关闭。原实现为兼容旧配置，在恢复 GPS 自动查询默认时显式写入开启；这使其不能真正跟随默认，也与其他字段的恢复语义不同，因此不再使用。配置版本 3 中省略该项统一跟随当前默认；版本 1／2 仍按旧规则解码，首次打开升级时将原有有效开关值明确保存，再写版本 3，防止自动开启原先关闭的查询。恢复默认从当前日志末尾开始处理，不补发已有文件。

字段标题行最右侧以主题色、小号文字常显「已显式指定」，表示显式配置，与数值是否恰好等于默认无关；其左侧的「恢复默认」仅在字段悬停或键盘聚焦时显示，触屏常显。跟随默认以灰色「已跟随默认」在字段悬停或键盘聚焦时显示，触屏常显，不再显示不可操作的恢复入口。编辑草稿立即更新来源显示，恢复仅删除该字段的显式配置；GPS／AI 保存明确列出修改字段，未改字段保持原有显式／缺省状态。API 从原始 TOML 推导来源，修订摘要包含配置存在性，防止数值相同但来源变化时覆盖过期编辑。

原先普通设置、GPS 与 AI 分别维护保存／重新加载按钮和草稿，不符合整页设置的操作预期。现统一由页面顶部按钮提交和重载三个分区的草稿；一次 `PUT /settings` 携带普通字段修改及可选 GPS／AI 修改，后端在资料库和配置锁下统一决定自动处理启用边界，一次校验并原子写入 `kist.toml`，再发布运行时快照。任一分区校验失败或修订过期时全部不写入，草稿保留。原 GPS／AI 保存接口保留兼容，但转调同一写入路径；AI 修改继续要求本机访问，不能借统一接口绕过限制。登录、断开连接、访问凭据管理和后台任务控制仍为独立即时操作，存在未保存配置时禁用会冲突的操作。

迁移先持久化完整新配置，再清理旧配置；中断后以新配置为准，避免旧凭据被重新导入。旧格式版本不认识时拒绝迁移。主库/客户端模式互相拒绝误开。

未保存状态按最终值和配置来源与保存快照的差异计算，不按是否发生过编辑计算。显式指定的值改回原值时清除差异；继承字段编辑后恢复继承也清除差异；数值相同但继承／显式来源改变仍须保存。容量按字节比较，列表按保存时的去空白、空项规则比较，同时保留原始输入草稿，避免打字过程中的空行被清掉。

设置页存在普通设置、GPS 或 AI 的未保存配置草稿时，站内跳转使用共享弹窗提供「保存并离开／放弃并离开／继续编辑」，默认聚焦继续编辑；保存失败保留页面、草稿和目标地址，并在弹窗显示错误。侧栏导航、当前标签页链接和浏览器前进／后退均保护草稿，同页目录跳转不拦截。浏览器关闭、刷新及跨文档历史跳转采用原生 `beforeunload` 提醒，浏览器不允许自定义其文案或加入保存按钮，不承诺关闭时异步保存；无修改时不安装提醒。登录、任务控制等即时动作不作为配置草稿。

## 生效与入口

原先把服务参数、资料库时区和投影方式都标记为重启生效，是因为实现只在启动时读取，而非业务上的限制。2026-10-24 用户确认改为统一热重载：只有监听地址保留重启生效；网页保存与 Unix SIGHUP 共用重载入口。Windows 网页保存同样直接重载，不依赖不存在的 SIGHUP。

保存前验证配置和运行前提（包括投影方式能力），成功后持久化并发布新的不可变运行快照；失败不替换正在使用的快照。服务请求固定使用进入时的上传限制、地图和访问控制快照，已有续传会话不会因缩减限额而失效。不重开资料库、不重启上传及媒体后台任务。命令行显式参数继续优先，监听地址及对应本机 Host 保持实际绑定值。手动编辑文件后需发送 SIGHUP 激活服务和资料库运行参数；主题、缓存、连接与凭据仍沿用按需读文件的即时语义。

资料库时区和投影方式采用原子快照，时区改变不重写原文件、不重算既有操作；新时间解析和后续查询使用新时区，历史重放依赖既有 payload。投影方式只用于后续创建或修复投影，保存和重载本身不触发 relink，不批量转换已有投影。地图资源的 CSP 随新页面响应更新，因此网页保存地图选项后刷新当前页面。资料库时区不能因迁移或省略而随设备改变。

「设置」与「数据同步」为独立页面，导航中设置在前、数据同步在后。两页均平铺全部分区，不使用隐藏内容的标签页，保证浏览器搜索可达；悬浮目录在宽屏右侧竖排，窄屏回到正文上方，只负责页内定位；分区以标题和留白区分，不加横向分割线。设置标题、重新加载和保存操作吸顶，目录及分区跳转按顶栏实际高度避让。数据同步保留同步状态、待提交修改、冲突、离线内容和本机操作；连接和缓存策略移到设置并提供链接。统一用户文案为「本机 / 远端」。空队列不意味着远端没有更新，不虚构上次同步时间。

### 默认时区与投影方式

原方案是新格式省略资料库时区时固定使用 UTC，初始化优先写入探测到的 IANA 时区。2026-10-30 用户明确要求默认值改为 `Asia/Shanghai`：新建资料库、省略时区和恢复默认统一使用该名称，初始化仍显式写入时区，但不再优先跟随宿主机。原方案使设置默认与初始化行为不同，且 UTC 不符合当前用户的默认使用需求；不选择只改前端默认或保留新建时的自动探测，以免不同入口得到不同默认值。已有明确配置（包括 UTC）保持原值，不重新计算已保存的时间事实。版本 1 依赖系统时区的旧配置迁移仍固定为当时的 IANA 名称，无法确定名称时明确要求配置，避免改变旧数据解释。客户端继续继承所连接资料库的时区。

旧实现启动时总重新选择最快的链接方式，不适合现在允许用户编辑的设置：用户指定 copy 会被重新改回 reflink。现在显式方式在启动时验证，不可用时报错；省略时自动探测而不写回。没有选择静默降级，是为了不把用户指定的空间占用和隔离语义悄悄改变。已有投影不会因改设置自动重建，可用 relink 重建。

2026-10-23 用户要求暂时移除网页中的修复来源配置，待后续研究。设置 API 不再公开此可编辑字段；既有 `[[remote]]` 配置和命令行修复能力保留，保存其他设置时不删除已有来源。

容量设置的网页输入使用现有依赖 go-humanize 解析带单位字符串，设置 API 同时兼容整数；TOML 仍保存整数字节，不改变旧配置语义。GB/G 为十进制，GiB/Gi 为二进制。网页只用能精确还原的单位显示容量，避免编辑时因四舍五入悄悄改变限制。启动参数覆盖提示与恢复默认同行，并使用主题色。

地图相关配置独立为「地图」分区。存储区新增本机原文件、资料信息（数据库、操作记录和辅助索引）、缩略图与预览缓存的只读统计；使用独立请求及手动刷新，不阻塞设置加载或保存。按现有文件长度汇总，排除 boxes 投影及上传/下载工作区等临时数据，不声称是文件系统分配块的精确占用；不跟随符号链接。离线端只计算本机留存及下载内容，按派生描述将共享缓存对象区分为原文件和预览，同一对象只计一次。扫描允许并发变化，可取消、不写日志或缓存状态，不构建新的持久索引。

访问凭据支持可选备注，创建时填写、之后可编辑或清空，保存在同一条 kist.toml 授权记录中。备注是展示信息，修改不生成新 token、不改摘要、ID 或创建时间；旧无备注凭据继续有效。撤销后的记录不可通过修改备注重新创建。备注长度最多 200 个字符，列表只返回备注及非秘密身份信息。

凭据列表采用紧凑表格，备注、ID 和创建时间分列，编辑/撤销在最右侧；行间轻分隔并支持整行悬停和键盘焦点背景。创建入口位于列表上方，点击后展开行内备注表单，确认或取消后收起，避免常驻输入框与既有凭据混淆。
