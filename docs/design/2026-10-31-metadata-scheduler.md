# 普通元数据与 AI 提取统一调度

状态：2026-10-31 用户要求补齐此前已确认的队列工作，已实现并验收。

普通 metadata 使用现有 runtime.db 的 background_jobs／queue_controls／job_attempts，按文件和内容版本排队，任务类型为 metadata，复用分页明细、暂停、补全、重试与单文件入口。本地提取器列表、版本与顺序来自 extract 注册表，不新增手工维护的 media／exif 清单。已有提取结果、人工修改与删除保护沿用归档内核。

服务端根据归档操作边界自动发现导入和覆盖后的文件，不依赖浏览器保持打开；首次运行也补齐现存文件缺失的本地提取结果，不强制重提取已完成结果。后台扫描进度与任务持久化，重启继续，失败不无限重试。普通任务失败不暂停整个本地处理组，仍允许手动暂停自动／批量处理。人工单文件请求沿用可越过批量暂停的规则。

普通 metadata 的任务优先级高于 AI／GPS，在每个任务边界重新选择；相同优先级保留轮转，避免方向批量任务压住所有 OCR。优先级由任务类型定义，没有用户调整单项优先级的需求，因此不冗余保存数据库列。所有提取共用 OS worker 锁，跨进程不并发执行；不抢占在途模型请求。AI／GPS 在本地 metadata 未就绪时排入前置任务并等待，本地提取成功后才继续。暂停前置组时依赖任务等待，不绕过暂停偷偷提取。

本地每个文件限时一分钟；上下文传入提取器、文件读取与提交检查，不在超时后遗留可写入的后台 goroutine。普通提取成功仍经 library 生成 extract_metadata 日志，任务完成晚于归档提交，使用既有请求去重／版本检查衔接两库；不新增归档 action、载荷或物化索引。未知类型也记录已处理，避免反复扫描无 EXIF 的文件。

文件模块的手动重新提取也排入本地队列，携带目标提取器；旧同步提取 HTTP 接口保留兼容，离线客户端仍可本地执行。NAS 上传完成后前端只刷新目录，不再下载整个归档盒列表逐项发提取请求；按需缩略图／预览与视频执行器继续独立，缓存限制和租约不变。

验收使用合成文件，覆盖无人打开网页时导入／覆盖处理、优先级、前置依赖、暂停、坏文件隔离、重试、中断恢复、同文件请求去重、人工值保护、超时、rebuild 和深校验；UI 复用现有表格与任务按钮，并同步 API fixtures。


## 验收结果

合成测试覆盖任务优先级与新导入重新获得优先权、暂停前置依赖、同文件重提取目标与请求去重、失败隔离、覆盖后自动处理、本地中断恢复、取消读取、归档 rebuild 与深校验。真实 API 测试启动服务生命周期后直接导入，未打开网页、未连接 AI 也会完成普通提取；现有 AI 队列回归仍保留中断不自动付费重试的行为。

前端完整测试通过（439 项），后续模式边界调整另跑受影响测试；API 契约、视觉场景与构建同步检查。Chrome 在独立合成资料库验证六行后台任务表格、独立暂停、CLI 导入后继续自动完成、失败文件及归档盒明细、恢复内容后显式重试归零，并检查深色桌面与浅色窄屏。原件读取失败仅用可恢复的合成文件移动测试，验收后已恢复；未将个人文件或模型输出加入仓库。
