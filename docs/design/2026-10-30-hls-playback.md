# 视频按需 HLS 播放

状态：2026-10-30 用户确认采用 HLS；已实现并通过本机合成视频与浏览器验收。

## 决定

NAS 网页视频播放使用 HLS 点播清单和短 MPEG-TS 切片，随程序按需加载的 hls.js 播放，不支持 MSE 时回退原生 HLS。切片统一 H.264/AAC，沿用现有 1080p 边界、保留比例和字幕入口；首版统一 30 fps，使六秒边界落在固定帧边界。清单先给出完整时间轴；只有请求到的切片才转换，跳转不需要转完前面的内容。hls.js 暂停时停止继续读取，原生 HLS 的缓冲由浏览器管理；离开详情销毁播放器并取消在途请求。HTTP 请求取消必须终止对应 ffmpeg，不启动全片后台转换。并发编码单独串行限流，不阻塞缩略图或 metadata 调度。

切片首版为 6 秒，每段独立关键帧，可单独生成与淘汰；输出时间戳对应完整视频位置。每段限制 90 秒、32 MiB，ffmpeg 两线程，输入只允许本地受支持容器，不读取上传清单或网络地址。原始 blob、op 和归档数据库不变。播放配方版本绑定清单及切片地址；旧地址不能返回新 blob 的内容。探测结果和切片索引保存在 runtime.db，网络轮询不读整份 JSON 状态。

切片可能因淘汰或外部工具升级重新编码，不能假设相同配方始终产生相同字节。响应使用实际输出 SHA-256 作为 ETag，浏览器私有缓存需重新验证；不对这种 URL 声明 immutable。hls.js 的 worker 随前端打包，通过同源 URL 加载，不访问 CDN 或放宽 CSP。

## 缓存

视频切片放在独立 transcodes/，不与 derived/ 缩略图及其他预览共享额度。默认视频缓存 8 GiB、最近访问 30 天，两项可配置，另提供显式清空入口。按最近访问淘汰，正在生成或读取的内容由 OS 租约保护，不能被另一个进程清理。空间不足且无法淘汰时明确报错，不突破额度。临时输出有独立体积上限，统计包括临时字节，最多一个编码器的额外 32 MiB 工作空间；缓存额度约束已发布切片。失败不发布部分切片。崩溃临时文件在取得编码器锁后回收；索引与文件不一致时重新生成，不修复或重建 runtime.db。

清理仅适用于可再生视频播放缓存，绝不删除原件、归档日志、提取结果、任务历史或缩略图。存储用量中增加独立“视频转码缓存”，旧 preview_1080p_v1.mp4 也按视频缓存展示，但不自动清理或迁移旧文件。

## 与旧方案和客户端的边界

旧方案先后台生成整份 MP4 再播放，大视频首播需等待完整转换，且与经常复用的缩略图一起统计，不能满足按需播放与独立淘汰的要求，因此替换 NAS 网页播放入口。旧 MP4 派生接口保留，用于现有离线准备和客户端协议；不破坏已经缓存的离线视频。本阶段不为客户端增加在线 HLS 中继或 HLS 离线下载协议。

不选择自己实现解码内核：用户已决定允许 NAS 实时转码。不选择 mpegts.js：它侧重连续直播，TS 点播跳转尚不支持，FLV 分段使用自有 JSON 清单；HLS 的标准清单、时间轴和分片加载更符合归档点播。不使用“m3u8 + FLV”，这不是 HLS 标准切片组合。首版只提供一个兼容质量，不增加多档码率、硬件编码或自动原视频编解码协商。

## 验证

仅使用合成视频验证清单、首次播放、跨片连续播放、未缓存位置跳转、尾段、无音轨、取消、租约、缓存淘汰、版本拒绝和缺依赖。前端验证播放器销毁和停止读取、字幕、实况照片及离线旧入口。私密测试库和用户文件不进入 Git 或视觉 fixtures。
