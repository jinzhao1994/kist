# Fileset 设计

- 更新：2026-10-20，用户授权实现。
- 基线：main `88d08f3`，v0.1.5。
- 权威边界：ops 与 blobs；所有配置变更经过 library，一条 op、一个 SQLite 事务。

## 当前决定

Fileset 是非根 folder 的可选配置，名称取 folder.name，独立于主文件名；成员归属仍只有 folder 树。配置包含稳定字符串类型、自动或手动主文件选择、投影布局和有序成员角色。SQLite 使用 filesets 与 fileset_members 多行存储，API 和 payload 用完整列表；position 为连续整数，整体更换列表在事务内原子完成。

类型为 live_photo、video_subtitles、document_pages。自动主文件分别为图片角色、视频角色、第一页（子组合递归解析）；手动指定实际后代文件。空或缺少角色的组合可保存，缺失主文件时显示名称和不完整状态。修改页序会改变自动主文件，不影响手动主文件。成员默认不按名称持续重排；初始化顺序展示后由用户保存。成员配置引用直属文件或直属子 fileset；手动主文件允许引用后代实际文件。

标签与 metadata 直接属于当前有效主文件，普通 folder 和 fileset 都不另建标注存储。切换主文件不迁移标注。组合界面修改标注时需绑定用户所见文件 ID，避免并发切换后误写新主文件。

默认检索普通文件与组合主文件，组合显示为一项；不匹配其余成员。开启「包含组合内文件」后，其他成员可独立命中。UI 复用搜索栏的条件编辑器，以「组合内文件 = 包含」呈现，随其他条件一起提交；不再在工具栏常驻独立复选框，移除该条件恢复默认范围。主文件标签、日期、类型按单文件条件计算，NOT 不跨成员提升。关键词覆盖组合名和主文件名，名称条件针对组合显示名。空组合无主文件属性，但仍可按组合名称浏览。原文件 API 保持兼容，新组合结果使用明确身份与模式，分页在过滤之后执行。

组合打开时复用普通文件的 Gallery 详情页（返回、前后切换、详情侧栏），标题为组合名，预览区按类型提供翻页、动态播放或字幕选择。翻页不改变侧栏所绑定的主文件标注。成员配置与目录入口收进更多操作菜单，不把组合预览放进目录浏览页；目录只用于明确查看成员。

组合大小沿用 folders.total_size（逻辑字节总和），不覆盖主文件 file:size；名称排序使用组合名，拍摄时间和导入时间使用主文件，更新时间反映结构与成员修改。嵌套在当前浏览范围内以最外层组合呈现，进入组合可查看成员。

投影可平铺或保留目录，平铺使用共同前缀及角色后缀。实际输出目录统一消解碰撞，视频和字幕共同调整前缀；不得把路径下划线拼接当作唯一性保证。内部相对引用敏感时保留目录与内部名字，不改原 blob。规划确定、增量与 relink 一致，失败记投影脏标记。

取消组合仅删除配置，保留目录、文件和标注；整体回收/恢复保留全部配置与成员注释。单独删除手动指定的主文件需先更换选择；删除其他成员时将角色变化写入同一条删除操作，逆操作恢复原配置，拒绝覆盖后来的编辑。自动选择根据保存的角色与页序解析，不自行猜文件名。

## 操作契约与交付

新增 set_fileset，before/after 完整配置表示创建、编辑、取消；逆操作交换 before/after，严格比较当前配置。targets 包含 box、配置中引用的文件和祖先目录，改变内容（投影与组合阅读顺序变化）；历史采用独立 op_filesets 索引，可从 payload 重建。删除/恢复沿用已有范围快照并扩充可选组合快照，旧 payload 缺省为空，旧日志不重写。成员删除联动使用显式前后配置，Apply 不在重放时选择角色。

依次交付内核与投影、查询/API、UI。检查普通写入、catch-up、rebuild、snapshot、verify --deep、严格撤销、并发冲突和跨平台投影。UI 复用当前菜单、Media、Gallery、标签弹窗、搜索 URL 与视觉规范。首版手工将现有目录配置为组合，不实现自动配对、通用 metadata 查询或新媒体类型。

## 被替换的草案与理由

2026-10-17 草案曾建议组合独立标注、任意成员命中归并整体。用户随后明确接受主文件改变时标注跟随改变，成员通过「包含组合内文件」独立检索，故取消独立标注表与跨成员归并。原理由「换主文件不能改变整体标注」不符合用户需求；不选择复制标注或迁移到新主文件，避免修改原文件事实。此前手动必选主文件的建议也被自动角色选择替代；自动模式并不意味着导入时自动识别组合。

以下保存原草案供理解替代方案，**不是当前实施要求**。

## 1. 已确认的产品方向

Fileset 将关系紧密的文件作为一个整体浏览和使用，同时保留每个成员的原始格式、身份与独立访问能力。

- 首批场景：Live Photo、视频及字幕、多页证件；允许嵌套，例如证件的每一页都是 Live Photo。
- 可以基于 folder 的树结构实现；逻辑容器不必对应一个物理目录。
- 成员仍可独立挂 tag、metadata，也可独立被检索。预览提供返回所属组合的入口。
- 整体标注不借主文件保存，不自动向成员复制。封面、播放入口和权威原件不是同一种角色。
- 检索开关叫「包含组合内文件」。关闭时默认将 fileset 作为整体展示；具体匹配与否定语义见第 3 节，尚待确认。
- 投影按类型及参数控制。平铺时使用共同前缀；相对引用敏感的类型可保留目录结构。
- 前缀拼接不是唯一性保证：`a/b_c` 与 `a_b/c` 都可能生成 `a_b_c`。

## 2. 推荐模型（待定稿）

复用 folder 树作为唯一的归属关系，在非根 folder 上附加 fileset 描述。普通 folder 没有该描述。成员归属继续由 `files.folder_id` / `folders.parent_id` 表达，不另建一棵所有权树。

建议 fileset 描述以 `folder_id` 为主键和外键，保留稳定的整体身份。整体标签和 metadata 引用该描述；普通目录仍不可标注。成员角色表只表达角色、顺序等事实，不重复表达所有权；角色引用必须属于该组合的直属成员。页面可以引用 file 或子 fileset，图片和视频角色引用 file。

配置采用版本化的稳定字符串 enum 与分类型载荷：

| 候选类型 | 角色与展示参数 | 投影倾向 |
|---|---|---|
| `live_photo` | 静态图片、动态视频 | 同前缀、不同扩展名 |
| `video_subtitles` | 主视频、字幕成员、语言、默认字幕 | 同前缀，字幕带语言后缀 |
| `document_pages` | 有序页面、可选封面 | 平铺或独立目录，页面后缀明确 |

这些名字和类型校验还不是持久协议。首版不引入插件体系，不自动识别组合，不扩展到网页或三维模型专用预览。

需要查询或反查的类型、角色、成员引用应提取为列或索引关系；不能靠查询 op JSON。不能用没有外键保障的任意 `target_type + target_id` 代替引用完整性。结构化配置与提取索引必须只有一个生成方向。

### 为什么倾向这个模型

- 独立 fileset 所有权树会与 folder 归属重复，跨 box 与移动需要维护两份位置。
- 仅在主文件保存整体标注，会使换封面、删主文件、拆组改变标注的归属。
- 把 File 改成可空 blob 的通用容器，会破坏当前一个 File 对应一个 blob 的清晰边界。
- 单纯 folder 预览字段不足以覆盖独立标注、组合级搜索和可平铺投影，因此需要明确的组合描述和契约。

### 必须先确定的生命周期

推荐整体删除/恢复以一条 op 包含描述、角色、标注、成员树与原有成员注释。成员单独删除、替换或移出时，不能留下悬空角色引用。

关闭组合展示、解散组合、删除整体是三种不同意图，不应共享一个隐含级联操作。特别是已有整体标签或 metadata 时，不能通过删除描述静默丢失它们。候选方案是首版拒绝带整体标注的取消组合，并提示先处理标注；另一方案是保留可恢复的停用描述。该选择尚未决定，不能先以数据库级联删除落地。

## 3. 检索草案与需要补清的语义

前次建议是：先对每个对象计算完整条件，再将成员命中归并到整体。不包含成员时返回整体及匹配位置；包含时成员独立出现，整体自身命中时仍出现。多成员命中归并、去重发生在分页之前。

候选公式（全库搜索，S 为最外层组合，P 为完整过滤条件）：

```text
match(S) = P(S) OR EXISTS descendant d: P(d)
```

不能改成逐条件从不同成员凑答案：A 有标签 X、B 有标签 Y，不代表存在一个对象满足 X AND Y。整体有 X、成员有 Y，也不会隐式继承后满足 X AND Y。

### 否定条件不是细节

该公式下，整体带 X、某个成员不带 X，查询 NOT X 仍会返回整体。这严格符合「某个对象满足完整条件」，但未必符合「排除带 X 的组合」的直觉。

两个候选：

1. 保持每对象完整匹配，NOT 也在对象内计算；将来增加明确的组合排除查询。
2. 给组合级排除单独定义语义，不能暗中将任意布尔表达式里的 NOT 提升到整棵树。

推荐先确认是否接受候选 1，并用例子固定。当前 UI 不新增 NOT 入口，但已有 TagExpr 与旧收藏包含否定条件，仍必须处理。缺失 metadata 的值如何参与否定也需在未来 metadata 查询中定义。

### 当前检索能力与范围

当前 Query 支持标签、类型、名称、日期等，并没有任意 metadata 条件。成员 metadata 可独立保存，不等于首版承诺通用 metadata 搜索；后者仍受 open-questions B8 的类型与数值索引问题约束。

需要确定并覆盖以下契约：

- 全库折叠到最外层组合；进入组合内部后，如何按当前范围折叠，避免搜索结果跳出当前目录。
- 名称、类型、大小、拍摄时间、导入时间、更新时间各自的整体排序值；不能用偶然命中的成员决定排序。大小是成员字节总和还是唯一 blob 总和、创建组合还是原件导入时间，都必须明确。
- 查询命中原因、定位路径与结果实体的身份分别返回；直接下载单个成员仍可用。
- 新结果类型和游标需要区分 file/fileset、折叠模式与排序；保留现有原文件 API/CLI 的契约，不能让旧消费者突然收到 folder ID。
- 新分段搜索、URL、收藏定义、标签结果与计数共用该语义；已有收藏和历史 payload 不改写。

## 4. 文件系统投影草案

现有 `projection.Plan` 每遇到 folder 就生成目录，其冲突检查按逻辑兄弟进行。平铺后必须改为按实际输出目录检查，同时覆盖跨组合候选、普通文件和目录。

推荐处理步骤：

1. 类型规则生成成员的相对布局与命名组；视频及其字幕属于同一命名组。
2. 平铺类型产生共同前缀与角色后缀；保留结构的类型仅调整外层目录名，内部相对路径不改写。
3. 统一净化并检查实际路径冲突，包括大小写、Unicode 规范化、保留名、净化碰撞和文件/目录碰撞。
4. 冲突时以稳定 ID 派生后缀消歧，同组共享前缀一起调整；短后缀继续碰撞时延长，不能假定固定四位足够。
5. 输出计划是当前状态的确定性函数。增量同步和 relink 使用同一规划器；投影失败记脏标记，不影响已提交的权威数据。

前缀编码不承担反向恢复层级的职责。原始名称与组合关系由日志保存，独立导出若要恢复关系，应另设计清单；首版不自动把这项列入范围。

嵌套时外层平铺、内层保留结构如何组合，需要完整例子；相对引用无法保留时必须明确报错或拒绝该布局，不能静默重命名内部文件或改原 blob。路径长度亦纳入规划与诊断。

## 5. 与现有架构的接入点

| 现有位置 | fileset 要求 |
|---|---|
| `domain.Folder`、`domain.File` | 保持单一归属，增加组合描述及角色值类型 |
| `library` | 持写锁追赶后校验引用、类型、深度；构造完整 payload |
| `oplog`、`Targets` | 新 action 明确 before/after、逆操作、整体历史索引与时间传播 |
| `EntryContents`、`BoxContents` | 删除/恢复、严格撤销必须包含组合状态；旧日志保持可重放 |
| `store`、snapshot、DiffViews、integrity | 新视图、外键和一致性检查覆盖写入、追赶、rebuild、历史、deep verify |
| `query`、wire/API | 混合结果身份、匹配位置、模式与分页；保留原文件访问 |
| `projection.Plan`、check、sync | 输出目录命名组分配；增量结果与 relink 一致 |
| Web 分段搜索、收藏、画廊 | 组合卡片、成员定位、模式持久化、三种类型的展示 |

新 action 的清单必须在编码前逐一确定：配置/角色编辑、整体标签、整体 metadata、成员修改联动、整体删除恢复。每项列出 handler、inverse、targets、是否改变内容、op 索引和 rebuild 行为。此草案不假定把旧 action 多加字段就安全：已发布载荷和严格撤销断言需要兼容性审查。

## 6. 建议交付顺序

1. **设计定稿**：确认第 2、3 节边界；补齐类型校验、生命周期、排序和 action 契约，原位更新 v0.1 相关决定及其失效理由。
2. **内核与投影闭环**：手工建立三类组合、编辑角色、嵌套、整体标注及安全删除恢复；包含重放与投影碰撞测试。先完成一条可独立验证的端到端路径。
3. **查询与 API**：折叠/展开成员、匹配位置与分页，接入新旧收藏；特别验证否定条件和多成员交集。
4. **Web 交付**：创建/配置、卡片、Live Photo 播放、字幕选择、多页翻阅、成员返回路径。遵循 UI 规范和真实浏览器视觉验收。

每个代码阶段交付前执行 `make check`，提交、push 并检查 CI；文档阶段执行 `git diff --check`。自动识别、通用 metadata 搜索和额外组合类型另行立项，不影响原始成员安全保存。

最低验收样例：嵌套的两页 Live Photo 证件；两集各带双语字幕的视频；`a/b_c` 与 `a_b/c`；与普通文件及目录的净化后碰撞；成员更改后的严格撤销拒绝；整体回收恢复；分页边界上的多成员命中；全历史重建与增量投影一致。
