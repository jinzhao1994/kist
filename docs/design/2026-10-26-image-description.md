# 图片描述 metadata

2026-10-26 用户授权实施 desc，并明确它属于 metadata，不是文件自身的描述字段。用户已确认首版只支持图片，生成简短客观描述，突出主体、场景和用途；PDF、音视频和 KV 不属于本轮默认范围。

## 语义与存储

逻辑提取器为 `desc`，正文保存为 `desc:text`，另存 `desc:model`、`desc:recipe`，以及可编辑的 `desc:hint`。2026-10-28 用户确认精简记录：模型字段改为包含服务商前缀（如 `openai/gpt-6-luna`），不再单独保存 `desc:provider` 和 `desc:language`；旧方案与取舍见 [OCR 实施记录](2026-10-25-ocr-mvp.md#精简模型与生成语言记录2026-10-28)。不写文件属性、归档盒描述或 OCR 正文。正文仍是 `text` metadata，最大 16 KiB，超限拒绝而非截断；此前只给 OCR 开放长文本的限制扩展到这一明确用途，其他字段继续保持 1024 字节边界。不引入 blob 引用、查询索引、schema 或新 action。

沿用 `extract_metadata` 的来源所有权、墓碑保护、严格撤销、快照、重建与同步。成功结果写入日志；重放不调用模型。描述和 OCR 使用独立提取版本，任一任务失败不覆盖另一任务的结果。生成与提交之间校验源 blob、metadata 和提取版本。

## 语言与生成

增加独立的 `library.language` 设置，默认 `zh-CN`，使用有效的 BCP 47 语言标签；与浏览器界面语言分离，在服务端读取。语言用于生成请求，不另存结果语言快照。修改语言或模型只影响后续任务，不自动改写成功结果。

描述提示词作为提供方无关的独立文本文件嵌入。默认一小段、一至三句话，聚焦可见主体、场景、动作及明确的文档类型，不转录全部文字，不虚构身份、地点、日期或关系。图片中的文字作为资料而非指令。继续使用当前连接的默认模型和 AI 代理。

2026-10-27 根据实际病历图片调整描述提示词（`desc:recipe = 2`）：此前统一强调画面主体和外观，导致描述只提纸张、条形码和栏目，遗漏明确可见的就诊日期、医院和科室。文档类图片改为优先概括文档类型、相关日期、机构、科室及主题，允许引用关键文字；普通照片仍概括主体、场景与动作。日期必须读自文档并明确其用途，不以照片拍摄时间替代，不猜测缺失信息。继续保持简短描述，不改成全文 OCR 或逐字段罗列。仅影响后续生成，已有成功结果和提取完成标记不自动改写。

2026-10-27 继续调整为 `desc:recipe = 3`：文档描述优先包含清晰可读且角色明确的相关人姓名（如患者、证件持有人、合同当事人），与日期、机构及主题一起帮助辨认材料。此前未明确要求姓名，导致病历摘要遗漏归属人；不采用枚举全部人名的方式，避免把医生、签署人等误当作材料主体。姓名或角色不清晰时省略，不猜测；直接写识别信息，减少“这是一张……”等泛泛开场。仍只影响后续生成，已有结果通过「重新提取」更新。

## 队列与界面

复用 OCR 的串行执行、持久队列、输入保护、暂停及明确重试机制；两类任务共享进程间 worker 锁。描述有独立的自动开关（默认关闭）、启用日志边界、队列状态及已有图片补全入口，不能沿用 OCR 的启用边界而自动回填旧图片。已完成任务跳过，失败／中断不自动重复请求。

先支持 JPEG、PNG、静态 WebP，共享输入检查及透明底处理。2026-10-27 用户授权扩展静态 HEIC / HEIF，复用 OCR 的后端全分辨率转换，输入与失败边界见 [OCR 的 HEIF 输入说明](2026-10-25-ocr-mvp.md#heic--heif-图片输入2026-10-27)。文件详情在 metadata 的“描述”分组展示正文和来源信息，复用紧凑三行预览、原文复制及校验值折叠。设置增加资料库语言与描述任务控制。PDF 等新输入需单独决定解析和页界，不能因后端支持文件输入就隐式发送全部文档。

## 手动重新提取（2026-10-27）

用户授权在元数据模块右上角统一提供「重新提取」：桌面悬停显示，键盘聚焦和触屏可见。EXIF 与 GPS 均调用 EXIF 提取器（两组一起刷新），Media 调用媒体提取器，OCR 与描述使用当前 AI 模型、代理和资料库语言。File 是导入时记录的事实，不能从归档副本还原原始 mtime，不提供重提取；离线客户端允许已有本地提取器重跑，AI 仍只在主库运行。

显式 force 仅绕过完成版本的跳过逻辑，不绕过字段来源所有权、用户墓碑和提交时的冲突检查。重新提取成功才通过 library 追加原有 `extract_metadata` 操作；失败、排队和处理中保留旧值。原 action 的 inverse、targets、内容影响、日志索引、snapshot 和 rebuild 语义不变，不新增 schema 或 action。普通自动任务与补全仍跳过已成功结果。

AI 重提取持久化 force 标志并使用调用方稳定请求 ID 去重。旧结果存在不能视为本次任务成功：崩溃恢复查对应的持久请求回执；无回执的中断不自动重试。队列返回本次刷新状态，即使文件已有成功结果；重复 HTTP 请求不得再次调用模型。失败沿用暂停与显式重试机制，界面保留旧结果并提示到 AI 设置恢复队列。

2026-10-28 按用户确认的输入／输出边界，不再保存 `desc:input_sha256`；它原来仅是来源快照，不用于去重或提交校验。提交时仍校验源 blob 和 metadata，旧方案与方向的内部版本保护见 OCR 实施记录末尾。


## PDF、Word 与 PPT 描述（2026-10-28）

用户授权扩展 PDF、DOC/DOCX、PPT/PPTX 的 metadata 描述，XLS/XLSX、CSV 暂不支持；本轮不扩展全文 OCR。此前仅图片的边界用于验证登录及图片链路，如今已有明确的文档需求和现成 Office 转换能力，因此扩展输入，而非新增独立结果类型。

文档走独立的可选 `ai.DocumentDescriber` 能力。PDF 经 Poppler `pdfinfo` 检查页数，再由 `pdftocairo` 重绘选定页面；Word/PPT 先复用预览的 LibreOffice 转换器，再走相同路径。重绘保留可见文字及页面图像，不发送附件或未选页面。不能仅取文字，因为扫描件、插图和幻灯片图表也需要参与理解；不把非 PDF Office 原文件直接交给提供方，避免其纯文字提取遗漏图片。OpenAI 通过 Responses 的内联 PDF `input_file` 发送，不依赖 ChatGPT 登录未开放的 Files 上传 API；其他后端缺少文档能力时明确失败。

默认最多前 10 页、发送的 PDF 最多 20 MiB；源文件上限 128 MiB，准备阶段最长 150 秒，Office 仍沿用 120 秒与 512 MiB 临时目录边界、格式验证及外链/宏限制。超过页数只发送前段，选定页面超过体积上限则失败，不默默丢弃页面；缺工具、需要打开密码、损坏、取消均不写成功结果。页数与字节共同约束输入，仅限制摘要字数不能限制模型输入成本。

新生成的描述（图片与文档）限制为 1024 UTF-8 字节，提示词先要求简短，超出时按完整字符截断并添加省略号；异常超过旧的 16 KiB 安全上限仍拒绝。此前生成结果只受 16 KiB 存储上限约束；现在区分简短摘要的生成预算和人工编辑/历史内容的存储边界，后者保持 16 KiB。`desc:recipe` 更新至 7。文档新增 `desc:coverage`，如 `1-10/28`，界面显示“第 1–10 页／共 28 页”：这是结果覆盖范围，用于判断摘要完整性，不恢复已取消的 SHA、语言、旋转等输入快照。被截页时提示词同时要求正文说明仅基于开头部分。

沿用描述独立的自动开关、新增边界、手动提取/重新提取、补全与暂停语义。旧文件只由显式补全或单文件请求触发；图片仍先方向校正，文档不进入图片方向或 OCR 流程。继续保护人工正文、补充信息与墓碑；提交时核对快照。沿用原 action、inverse、targets、索引和重建，不改 schema，不迁移或删除旧字段，不重写已有结果。专用提示词位于 `internal/ai/prompts/document-description.txt`，与服务商无关。

2026-10-28 修正 PDF 加密判断：原实现拒绝所有 `Encrypted: yes`，但无需打开密码、仅限制复制或修改的 PDF 也带此标记，导致能预览的文件无法生成描述。改由无密码的 `pdfinfo` 打开和 `pdftocairo` 转换结果判断是否可处理，仍不提供密码或尝试破解；真正需要打开密码的文件继续失败。保留原文件、页数、体积和超时边界，不因权限标记新增依赖或另做解密流程。
