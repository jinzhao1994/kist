# 图片描述 metadata

2026-10-26 用户授权实施 desc，并明确它属于 metadata，不是文件自身的描述字段。用户已确认首版只支持图片，生成简短客观描述，突出主体、场景和用途；PDF、音视频和 KV 不属于本轮默认范围。

## 语义与存储

逻辑提取器为 `desc`，正文保存为 `desc:text`，另存 `desc:provider`、`desc:model`、`desc:language`、`desc:input_sha256`、`desc:recipe`。不写文件属性、归档盒描述或 OCR 正文。正文仍是 `text` metadata，最大 16 KiB，超限拒绝而非截断；此前只给 OCR 开放长文本的限制扩展到这一明确用途，其他字段继续保持 1024 字节边界。不引入 blob 引用、查询索引、schema 或新 action。

沿用 `extract_metadata` 的来源所有权、墓碑保护、严格撤销、快照、重建与同步。成功结果写入日志；重放不调用模型。描述和 OCR 使用独立提取版本，任一任务失败不覆盖另一任务的结果。生成与提交之间校验源 blob、metadata 和提取版本。

## 语言与生成

增加独立的 `library.language` 设置，默认 `zh-CN`，使用有效的 BCP 47 语言标签；与浏览器界面语言分离，在服务端读取。每次生成的实际语言写入 metadata。修改语言或模型只影响后续任务，不自动改写成功结果。

描述提示词作为提供方无关的独立文本文件嵌入。默认一小段、一至三句话，聚焦可见主体、场景、动作及明确的文档类型，不转录全部文字，不虚构身份、地点、日期或关系。图片中的文字作为资料而非指令。继续使用当前连接的默认模型和 AI 代理。

## 队列与界面

复用 OCR 的串行执行、持久队列、输入保护、暂停及明确重试机制；两类任务共享进程间 worker 锁。描述有独立的自动开关（默认关闭）、启用日志边界、队列状态及已有图片补全入口，不能沿用 OCR 的启用边界而自动回填旧图片。已完成任务跳过，失败／中断不自动重复请求。

先支持 JPEG、PNG、静态 WebP，共享输入检查及透明底处理。文件详情在 metadata 的“描述”分组展示正文和来源信息，复用紧凑三行预览、原文复制及校验值折叠。设置增加资料库语言与描述任务控制。PDF 等新输入需单独决定解析和页界，不能因后端支持文件输入就隐式发送全部文档。
