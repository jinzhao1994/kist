# AI 结构化提取

- 日期：2026-10-29
- 状态：用户 goal 已授权实现、真实样本质量验证及搜索路径实验；2026-10-29 后续反馈简化字段命名、层级与展示。不包含发布。
- 范围：图片、PDF、Word、PPT 的 metadata 结构化事实；默认沿用 Luna。

## 数据与人工保护

动态字段、对象和重复记录用一个有界的 JSON 文档 `facts:data` 保存，属于逻辑提取器 `facts`。它不是文件 description，也不把模型返回字符串直接视为可信数据。JSON 使用带类型的字段树：每个节点有稳定 key、显示 label、type，以及标量 value 或 children；array 的 children 是各自带稳定语义 key 的 object。重复记录的身份不依赖数组下标。常见语义 key 由提示词约定，其他事实允许扩展。

2026-10-29 用户反馈后，单份证书／单条记录默认平铺在根 fields，不添加 holder、competition、education 等类别包装。姓名统一 name／「姓名」，记录的主要日期与地点统一 date／「日期」、location／「地点」，事件／考试名称用 title／「名称」；号码、组别、名次、分数等使用简短通用 key，不因证书类型换名。出生、有效期、签发等真实不同的角色仍须区分，不能为了统一而合并不同事实。只有多人、多条记录或冲突备选才保留对象／数组，记录内部仍使用相同通用 key。旧版用类别对象约束角色，但对普通单份证书过度细分，妨碍跨文件搜索，故不再作为默认形状。已有 outline 仍约束重提取的稳定路径，不自动迁移或清理旧测试结果。

fields／children 数组按文件阅读顺序保存；取消 Encode 按 key 排序。原排序用于降低模型换序造成的日志变动，但会丢失用户需要的原文顺序。重新提取按本次返回顺序合并，遗漏的旧字段按原相对顺序保留在末尾；人工值、删除标记及数组身份保护不变。旧结果已经丢失的顺序不能靠 key 还原。日期保留年/月/日精度，号码是 text，用时与分数分开，不确定字段显式标记。

保存的 JSON 包含格式版本和逐节点人工来源/删除标记。模型不能指定这些控制信息；后端解析后自行添加。节点 key 不由用户编辑，值可编辑；容器可显式删除。用户编辑一个叶子不会锁住其他叶子；删除容器会保护其整个子树。重提取按稳定路径合并，只增补和更新 AI 节点，不删除遗漏节点，不覆盖人工节点或其删除标记；结构类型变化拒绝本次提交，避免隐式删除原有子树。

重提取给模型提供已有字段的 key、label、类型及重复对象结构，作为路径约束，不提供旧字段值作为事实来源，也不发送人工删除节点的旧值。要求沿用已有身份，不因排序改变重建 key。不明确的重复对象归属必须保守处理；语义不同却同名的对象不得合并。仅靠自由生成 key 无法从理论上保证实体匹配，真实样本需要覆盖换序、字段纠正和重复提取，发现身份漂移须修正提示词或收紧校验，不把概率匹配包装成确定性。

`facts:data` 外层 metadata.source 表示负责该文档格式的提取器，仍为 facts；JSON 节点的来源才决定字段覆盖权限。它是主设计“单行标量”规则的显式扩展：JSON 整行 source=user 会使一个人工修改锁住全部事实，逐叶拆成普通行又需要另存数组身份和容器结构。选择单 JSON 保留关联，统一在 library 中合并。普通 metadata 的来源规则保持原样；facts 整行若被显式删除，原有 user 墓碑继续保护整份结果。

人工字段修改复用 `set_metadata`：请求带稳定节点路径及用户看到的整行 before 状态，library 生成修改后的完整 JSON，沿用严格 before 检查、原 action handler、inverse、targets、内容标记和 op 索引。Apply 只重放已经决定的 JSON，不在 Apply 推断、合并或生成身份。离线客户端用相同变更生成器。保守地把同一文档的并发修改视为冲突，避免静默丢失更新。重新提取仍走 `extract_metadata`；提交前检查源 blob 和 metadata 快照。无需新增数据库 schema 或 action；必须验证日志回放、snapshot、同步、撤销和 deep verify。

除 `facts:data`，只记录 `facts:hint`、`facts:model`、`facts:recipe`。不另存输入 SHA、旋转、语言或 coverage。JSON 有明确的总大小、深度、节点数、键名及标量大小限制，拒绝重复 key、未知控制字段、非法数值/日期和混淆类型。格式不合法时不保存部分成功结果。

2026-10-29 真实多页样本复测暴露了通用 key 的歧义：模型把主副页重复的证号及不同含义的档案号都写成 number，也把附注日期再次写为 valid_from。处理版本 3 明确同层 key 唯一，同一事实跨页只保留一次；主号码用 number，确实不同的档案号用 file_number，登记号用 registration_number，不按页码或序号制造新 key。日期区间拆为两个日期，主事件用 date/end_date，有效期用 valid_from/valid_until；附注若依赖其他日期或条件，保留 note 文本，不覆盖主有效期。保留短通用字段的原决定，不恢复类别包装。

后端继续拒绝歧义结果，不自动删除重复项、追加数字后缀或猜测日期含义。重复 key 错误标明同层位置，帮助对照本机执行记录，不在错误中加入字段值。这些规则保护未来索引的语义：number 与 file_number 可以分别检索，date/end_date 保持可比较的单日期，不把不同事实覆盖成一个值。跨文件同义 key 仍需规范和实测，不能把格式通过视为语义一致。

## 输入、提示词与界面

复用当前完整文档输入：最多 200 页和 20 MiB 转换后 PDF、源文件 128 MiB；图片先补齐方向并采用转正后的全分辨率输入。不依赖已有 OCR 或 desc 作为事实。提供方无关提示词放在独立文件中；后端只提供图像/文档推理传输，服务器负责结构校验与合并。

详情新增“结构化信息”组，复用 metadata 的编辑、复制、删除确认、来源图标、提示和标题栏任务状态。单份证书直接显示字段，必要的对象/数组按分组展开，标量按普通字段展示，提供完整值提示、编辑与删除，不提供复制按钮或点击复制；不把 JSON 源码编辑器作为默认交互。独立补充信息、手动重新提取、自动开关及查缺补漏沿用现有队列语义；自动仅处理启用后新增文件，独立启用边界，默认关闭。模型/代理设置共用。AI 任务共享串行 worker，方向先于依赖它的任务。

## 质量与隐私

原始证件/证书仅在用户授权的本机资料库与已连接的 OpenAI 之间用于验收；原件、截图、输出、核对表不进入仓库或 CI。测试仅用合成内容。建立本机私有样本清单，从原图逐项核对；已有 OCR/描述不是 ground truth。涵盖身份、旅行证件、驾驶资格、学历/学位、竞赛和体育成绩；关注角色、日期含义、号码、用时/分数、个人/团队和组别范围。难样本重复测试，提示词改动后回测其他样本，记录真实错误而非只报 JSON 通过率。

## 搜索路径

JSON 是持久化结果，搜索使用可重建的标量投影。候选索引行包含文件、字段路径、语义 key、类型、值及所属对象路径，嵌套重复对象保留祖先关系。固定索引服务所有动态 key，不为模型输出动态建列/建索引。姓名/号码精确匹配、日期精度范围、数值比较和同一对象的组合条件分别测试。人工删除与不确定值不作为确定事实参与查询。

本轮先用合成数据测量索引候选并查看查询计划，不上线未授权的完整搜索 UI，不在没有证据时永久增加物化表。数值存储 B8 仍须依据本轮实验讨论：允许实验独立类型列，不因此静默修改现有 file_metadata 的 TEXT affinity。索引若正式落地，必须和普通写入、追赶、rebuild、snapshot、deep verify 一起实现。
