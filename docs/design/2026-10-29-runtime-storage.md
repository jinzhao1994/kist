# 本机运行状态统一使用 SQLite

状态：2026-10-29 用户授权全仓库迁移，已实现。

## 边界

归档权威继续只有 ops/ 与 blobs/；kist.db、client.db 仍为可重建归档视图。客户端 pending/ 意图、回执与冲突决定继续使用持久日志，供网页查询的投影进入数据库。配置仍为 kist.toml，媒体、缓存及上传的内容字节仍为文件。

新增实例私有的 runtime.db，保存本机任务、执行记录、缓存索引、离线保留选择、同步边界、上传续传和限流状态。它不随资料库同步，也不由归档 rebuild、snapshot 或 verify --deep 重放或清空。归档备份 ops/blobs 可以恢复归档，但无法恢复这些本机状态；需要保留本机任务历史和保留选择时必须同时备份运行库。数据库损坏报错，不自动删除重建或丢失用户选择。

SQLite 使用 WAL、外键、busy timeout 和 FULL synchronous；数据库及包含私密返回的文件为仅本机用户可访问。网络和媒体转换不在数据库事务中执行。数据库锁不能代替保护外部文件、worker 生命周期和跨归档提交的 OS 锁；锁顺序必须保持一致。

## 表与调度

所有提取类型共用 background_jobs，通过 kind 区分；job_attempts 保存每次执行及错误、模型和原始返回（方向任务目前记录提供方解析后的结果）；queue_controls 保存暂停与自动/补全扫描进度。索引覆盖类型/状态/调度顺序、文件/内容版本和请求标识。原始模型文本不进入归档 metadata、普通日志或队列轮询响应，不自动清理历史；有明确字节上限与截断标记。不将整个 JSON 队列塞进一个数据库单元格。

媒体任务共用任务存储的调度字段，转换结果为非查询载荷。上传会话及逐文件进度、缓存对象及派生映射、离线保留关系、工作空间预留、同步边界与限流各自按职责建表。外部内容字节仍校验、fsync 后才推进已确认进度。跨文件系统与数据库的提交用可恢复步骤，不假设两者能共享事务。

方向先于 OCR/描述/结构化提取，单张任务可越过批量暂停，失败和中断不自动重复付费；缩略图独立调度。共表不等于把全部后台任务强制串行，也不引入通用工作流引擎。

## 迁移与兼容

旧实现将运行状态当作派生文件：AI 为整份 queue.json，媒体为每项 JSON，缓存和上传分别维护文件索引。原子替换与 OS 锁保证了一部分持久化，但网页查询、历史诊断和跨状态维护需求使多套文件状态机不再合适。选择结构化 SQLite 表，不选择通用 JSON 键值表，也不把运行状态混入可重建归档库。

迁移在旧子系统锁保护下进行，数据与迁移标记事务提交；失败不标完成，可重试。旧文件保留作迁移前备份，迁移后不双写、不再按缺失行回退到旧文件，避免删除或重试后旧任务复活。未知或损坏格式不静默跳过。切换须停止旧服务；新格式标记阻止旧程序重新打开已切换实例，不支持混用旧新版本或直接降级。运行库缺失时不得静默从过期备份复活任务。

## 验收

覆盖普通写入、重启、独立进程竞争、迁移中断重试、旧文件保留与不重复导入、数据库版本拒绝、归档重建及深校验独立性。上传覆盖字节/进度持久化边界与断点续传，客户端覆盖未同步意图保护、缓存配额和离线保留、同步边界及中继。合成数据检查查询计划和索引；不把个人样本、模型私密返回或令牌放进仓库及 CI。

执行列表按文件与任务类型建立索引，使用单调序号分页；普通轮询不读模型正文。正文上限 8 MiB，保留原始字节数与截断标记。旧失败状态可导入，但无法补回此前未记录的模型返回。AI 调度器保留既有批量扫描逻辑，逐项查询和网页统计使用 SQL；不宣称所有后台调度均为常数时间。升级及备份步骤见[运维说明](../operations.md)。
