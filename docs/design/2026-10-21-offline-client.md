# 笔记本离线客户端设计

状态：实施中。用户于 2026-10-21 授权，需求和验收清单见 [Goal 任务说明](../plans/2026-10-21-offline-client-goal.md)。本文确定当前实现方向；阶段完成证据单独记录，不能把本文当成实现已完成的证明。

## 1. 两种运行模式与权威

NAS 模式继续保存完整 `ops/` 与 `blobs/`，SQLite 及投影可重建。笔记本是明确的客户端模式，不冒充通过完整性检查的 NAS 库。它保存 NAS 元数据的缓存、本地待同步日志、未上传原文件与可逐出的下载缓存。网页与领域操作复用；NAS 的完整性规则不因客户端而放宽。

第一版同步完整元数据目录及正式历史，原文件和预览按任意对象需求下载，不按 box 划分所有权或同步边界。完整元数据不等于完整原文件副本。首次元数据同步未完成时不能把部分数据标成全集；缓存清理不删除待同步操作依赖的元数据。历史以有界分页传输，不要求把全部日志放进一次 HTTP 响应。

客户端本地权威是未同步日志及未确认上传的新内容，必须 fsync；已缓存的 NAS 历史和原文件可再次获取。本地 SQLite 不能独占 pending 状态、操作映射或冲突决定。客户端目录有独立模式标识，旧 NAS 工具必须拒绝误开，不能把客户端缺少原文件报告为 NAS 数据损坏。

## 2. 操作身份、时间与信封

NAS 继续使用递增 int64 op ID，代表正式提交顺序。本地操作使用随机唯一标识加本地序号；序号不具有 NAS 身份。内部临时物化使用的编号不得对外冒充正式编号。

正式日志增加可选同步信封，包含本地操作唯一标识、原始请求摘要、NAS 接纳时间。原始操作时间仍为 ts，接纳时间由 NAS 在写锁内决定。ID 与摘要支持相同请求返回同一个结果、相同 ID 不同内容拒绝。信封参与日志校验和，SQLite 中的同步索引完全由日志重建。

同步字段引入信封 v3；读取 v1/v2 保持原字节校验和及语义，不重写旧日志。普通本机操作无需同步字段。NAS 日志分桶按接纳时间（旧事件按 ts），并沿用时钟回拨钳制。日志扫描、历史分页、快照截止点始终按正式 ID。

新同步事件向 Apply 提供接纳时间作为物化变更时间，避免把旅行期间的旧时间赋给当前状态而使 updated_at 倒退。payload 中明确保存的创建时间、拍摄时间等原始事实不改写。旧事件仍使用 ts，保持旧重放语义。历史显示原始操作时间，并可查看接纳时间。

origin 只表示 user/extractor/maintenance 等操作性质，不表示网络传输或设备。离线人工操作仍为 user。保留旧 sync 值的解码和旧传播语义，不让新同步流程生成它。不新增设备来源枚举或历史中的设备名称；授权凭据与操作身份分离。

## 3. 本地编辑与同步状态机

本地可见状态是已确认 NAS 状态加本地 pending 操作。修改先生成完整、自足的领域操作，持久化本地日志后应用到物化视图。使用现有领域前提校验、逆操作和 ID 生成，不把整个 HTTP 请求盲目留到将来重新解释。

同步流程：能力与库身份校验 → 取得固定 NAS 日志上界 → 分页拉取至上界 → 重建本地基线并依序尝试 pending → 传输所需新 blobs → 依序提交 → 持久记录回执 → 再拉取 NAS 正式结果 → 重建可见状态。同步全过程允许 NAS 其他写入；每条接纳都重新在 NAS 写锁内验证前提。

pending 的原始记录不修改。回执、放弃决定、重做方案和撤销以追加记录表达。冲突时停止后续提交；用户保留 NAS 或重新选择本地结果后，依赖操作必须重新验证。不能在冲突中直接删除队列记录来让后续请求错误通过。

NAS 已提交而客户端未收到响应时，按同一个操作 ID 与摘要重试。回执查询早于当前状态冲突检查，避免已经成功且后来被撤销的操作在重试时被重新执行。冲突后的新方案使用新标识并记录与原始意图的关系。

pending 日志复用普通文件日志的校验和、fsync、跨进程锁和末尾断写恢复，但使用独立目录与本地事件序号，不作为 NAS 领域日志重放。入队、开始发送、确定拒绝、确认回执、放弃、重做分别追加记录。开始发送先落盘；网络失败保留“结果未确认”，禁止放弃或修改原意图，直到 NAS 回执或确定未提交的结果消除歧义。仅确定的服务端拒绝可记录为冲突，不能把超时当拒绝。重做保留原意图及原因，使用新 ID，并保留原逻辑排队位置；后续依赖原 ID 的操作不会被偷偷重定向，必须重新验证。任何未解决冲突或失效依赖都阻止越过它提交后续操作。

客户端物化重建在一个 SQLite 事务内先重放已确认前缀，再按逻辑顺序叠加 pending。每个 pending 使用 savepoint，前提失败时撤回该条，提交已确认状态与此前有效修改，并报告阻挡位置；数据库或日志读取失败则整次回滚，保留上一个可用视图。已确认日志中的同步身份优先于本地回执，可识别丢失响应；已取得回执但尚未拉到正式事件的修改继续叠加，避免同步中途消失。视图内的数字位置可能随重建变化，仅供内部索引使用，对外操作必须使用 NAS ID 或 pending 唯一 ID 的明确引用，不能把视图位置当成 NAS ID。新写入和 pending 重建共用状态约束检查，历史重放不追加新约束。

接纳协议 v1 使用独立 SyncProposal，不接收客户端伪造的正式日志行。请求摘要由 NAS 从完整提案计算，包含原始时间、操作、payload、依赖、操作组与撤销引用。时间必须可无损表示为现有纳秒时间；未知协议/操作和传输伪装的 origin=sync 明确拒绝。撤销请求只带目标引用，NAS 从已提交事件计算逆操作；不接受客户端同时指定撤销目标和任意 payload。提取操作必须声明实际读取的文件内容哈希，避免把断网期间旧原文件的提取结果应用到已被替换的版本。

## 4. 操作覆盖与冲突原则

所有现有写 action 都要进入显式同步能力分类，测试对照实际注册表，避免新增 action 默默缺失。下表是策略分类，不替代每个 handler 的实际审查。

| 操作族 | 前提、合并与撤销 |
| --- | --- |
| create_box/create_folder/create_tag/create_saved_search | 保留本地实体 UUID；父对象存在、同名唯一约束满足。相同同步 ID 重试取回执，不能凭同名合并不同身份。 |
| update_box/rename_entry/rename_tag/move_tag/update_saved_search | 校验用户所见 before 及父级、唯一性、循环约束；互不相关字段可按实际 delta 应用，同一字段竞争报冲突。 |
| tag_files/untag_files/tag_boxes/untag_boxes | 按原有来源/拒绝语义应用；对象仍存在，不因删除而复活。保留严格逆操作检查。 |
| import_files/upload_files | 原始实体身份和内容哈希不变；先完整入库 blobs，再提交，路径/替换前提不成立报冲突，不在 NAS 静默重新命名。 |
| extract_metadata/set_metadata | 保留提取事实、版本和 origin；验证原文件内容及原有 metadata 前提，不把过时提取应用到已替换内容。 |
| set_fileset | 完整 before/after 比较，保留成员和主文件引用；页序竞争按配置冲突，不能逐行随意合并。 |
| delete_box/delete_folder/delete_tag/delete_saved_search/delete_files | 检查当前对象、后代和引用约束，不能把 NAS 新增成员一并吞掉；严格撤销恢复所记录身份。 |
| delete_box_contents/delete_entry_contents/delete_fileset_entry | 比较完整删除范围快照及关联配置；NAS 新修改阻止删除，不扩张删除范围。 |
| restore_box_contents/restore_entry_contents/restore_fileset_entry/undo_upload_files | 保留恢复快照；检查当前名称、身份、引用及撤销阻挡条件，失败保留 pending。 |
| request_receipt | 协议产生的幂等结果，不作为用户可编辑领域命令；同步映射与请求回执不能互相冒充。 |

撤销引用以“NAS 正式 ID”或“本地操作唯一 ID”显式区分。NAS 接纳前把本地引用解析到已确认正式 ID；不靠本地数字巧合匹配。撤销/操作组关系进入正式日志，重建仍可得到同样历史。未知 action 或协议版本明确拒绝。

## 5. 缓存与传输

缓存区分元数据、预览和原文件；API 返回未缓存与真正读取/校验失败的不同状态。自动按需下载可中断和重试。离线目录与搜索使用明确的元数据同步状态，不把“未获取”当“不存在”。网页资源随本地二进制提供，远程地图等非必要外部资源离线时明确降级。

客户端配置 max_age 与 max_bytes；年龄基于最近访问，超龄逐出、超额按 LRU 逐出。容量包含显式保留项，但保留项不可自动清除，超过上限时提示调整。未上传内容与 pending 所需内容单独统计，不能淘汰。正在使用/传输的内容受租用保护；下载前预算，下载中限制实际体积，临时文件也计入管理，不能无限写入后再清理。

按哈希复用内容；续传核对前缀与最终整文件哈希，原子安装、fsync 后才允许 NAS 接纳引用。同步确认以 NAS 持久回执为准。fileset 离线准备递归收集实际预览依赖，循环损坏终止，未全部准备完不标“已离线”。缓存索引损坏可从缓存文件与持久保留清单恢复；恢复后不得误删唯一的 pending 内容。

## 6. 授权与边界

NAS 显式启用同步凭据，客户端绑定库 UUID。网络同步端点使用独立认证，不能把现有局域网网页的无登录假设扩散到同步授权。凭据保存在运行配置中，限制文件权限，不进入事件历史、错误响应或日志。支持撤销凭据，协议协商包括信封版本及允许的操作集合。

首次元数据复制固定日志上界，以已提交日志为源；不复制 SQLite，也不复制运行中不一致的目录树。主库写操作仍由 library 完成，所有同步判定在生成/接纳层完成，Apply 不访问网络、时钟或配置。

分页边界包含库 UUID、截止 op ID 和该事件校验和；各页在提交锁内确认边界仍匹配，再返回已验证的原日志信封。后续 NAS 写入不改变本次前缀。单页限制记录数与目标字节数，但旧的单个大事件必须整体传输，因此允许其独占一页并超过目标字节数，不能截断事件或重写校验和。当前先复用日志迭代验证；每页需要扫描固定前缀，后续如实测成为瓶颈再增加可重建的定位索引。

## 7. 既有方案的替换与验证

3.12 原先预留将 NAS op ID 扩成 (instance_id, seq)。本场景有唯一 NAS 权威，不需要多主排序：保留 NAS int64 顺序，独立本地标识映射足够。旧预留不是已实现协议，不据此改变历史 ID。

旧 origin=sync 预留混合传输方式与执行性质，无法保留 extractor 语义，故不采用。旧全量库复制适用于停止写入后的备份，不适用于可写 NAS 的部分缓存客户端；不弱化备份保证来迁就新功能。

分阶段验证：日志 v1/v2 兼容与 v3 信封 → 同步索引普通写入/追赶/rebuild/snapshot/deep verify → 客户端 pending 与缓存恢复 → 各 action patch 与撤销 → 传输中断和幂等 → 真实本地网页离线验收。每阶段检查通过后提交并跟进 CI；最终按 Goal 文件逐项审计。此阶段不发布版本。
