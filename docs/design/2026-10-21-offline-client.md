# 笔记本离线客户端设计

状态：实施中。用户于 2026-10-21 授权，需求和验收清单见 [Goal 任务说明](../plans/2026-10-21-offline-client-goal.md)。本文确定当前实现方向；阶段完成证据单独记录，不能把本文当成实现已完成的证明。

## 1. 两种运行模式与权威

NAS 模式继续保存完整 `ops/` 与 `blobs/`，SQLite 及投影可重建。笔记本是明确的客户端模式，不冒充通过完整性检查的 NAS 库。它保存 NAS 元数据的缓存、本地待同步日志、未上传原文件与可逐出的下载缓存。网页与领域操作复用；NAS 的完整性规则不因客户端而放宽。

第一版同步完整元数据目录及正式历史，原文件和预览按任意对象需求下载，不按 box 划分所有权或同步边界。完整元数据不等于完整原文件副本。首次元数据同步未完成时不能把部分数据标成全集；缓存清理不删除待同步操作依赖的元数据。历史以有界分页传输，不要求把全部日志放进一次 HTTP 响应。

客户端本地权威是未同步日志及未确认上传的新内容，必须 fsync；已缓存的 NAS 历史和原文件可再次获取。本地 SQLite 不能独占 pending 状态、操作映射或冲突决定。客户端目录有独立模式标识，旧 NAS 工具必须拒绝误开，不能把客户端缺少原文件报告为 NAS 数据损坏。

客户端目录以 `client.json` 标识，不生成 NAS 的 `kist.toml`。`pending/` 保存本地意图和决定，`local-blobs/` 保存未确认原文件；`catalog/` 缓存原格式 NAS 日志，`catalog-head.json` 标记完整验证的可见前缀，`catalog-transfer.json` 保存正在拉取的固定目标；`client.db` 为可重建视图，`cache/` 供可逐出内容使用。目录默认仅所有者可访问。配置中的缓存默认上限为 30 天、10 GiB，用户可调整；这不是未上传数据的上限，具体逐出机制另行实现。

同步能力携带 NAS 库的可移植时区名称，首次初始化、重新连接和同步时写入客户端设置，供之后生成新操作时解释无时区内容时间。最初客户端默认 UTC 的实现只适合显式低层创建；直接用于联网初始化会让非 UTC 库的 metadata 重算产生不同结果，因此联网路径改为继承 NAS。空时区、机器相对的 `Local` 或无法加载的名称拒绝，不能用笔记本时区或 UTC 静默替代。旧服务端未提供该能力时需升级；NAS 手工配置使用隐式本机时区时应先设置明确 IANA 名称。设置刷新不重写任何已持久化 pending payload，历史重放也不重新解释其时间决定。

目录分页先验证身份、连续 ID、原校验和与重试一致性，再持久追加；保留原信封版本，不重新生成 NAS 日志。未完整下载的前缀不会变成可见全集，重启继续使用上次完整边界并恢复传输游标。新本地修改先在回滚事务里验证，再写 pending 日志，最后物化；新内容必须已经保存在 `local-blobs/` 并通过哈希校验。NAS 已有内容可只引用、不下载，但不能修改该哈希对应的既有内容事实。

## 2. 操作身份、时间与信封

NAS 继续使用递增 int64 op ID，代表正式提交顺序。本地操作使用随机唯一标识加本地序号；序号不具有 NAS 身份。内部临时物化使用的编号不得对外冒充正式编号。

正式日志增加可选同步信封，包含本地操作唯一标识、原始请求摘要、NAS 接纳时间。原始操作时间仍为 ts，接纳时间由 NAS 在写锁内决定。ID 与摘要支持相同请求返回同一个结果、相同 ID 不同内容拒绝。信封参与日志校验和，SQLite 中的同步索引完全由日志重建。

同步字段引入信封 v3；读取 v1/v2 保持原字节校验和及语义，不重写旧日志。普通本机操作无需同步字段。NAS 日志分桶按接纳时间（旧事件按 ts），并沿用时钟回拨钳制。日志扫描、历史分页、快照截止点始终按正式 ID。

新同步事件向 Apply 提供接纳时间作为物化变更时间，避免把旅行期间的旧时间赋给当前状态而使 updated_at 倒退。payload 中明确保存的创建时间、拍摄时间等原始事实不改写。旧事件仍使用 ts，保持旧重放语义。历史显示原始操作时间，并可查看接纳时间。

origin 只表示 user/extractor/maintenance 等操作性质，不表示网络传输或设备。离线人工操作仍为 user。保留旧 sync 值的解码和旧传播语义，不让新同步流程生成它。不新增设备来源枚举或历史中的设备名称；授权凭据与操作身份分离。

## 3. 本地编辑与同步状态机

本地可见状态是已确认 NAS 状态加本地 pending 操作。修改先生成完整、自足的领域操作，持久化本地日志后应用到物化视图。使用现有领域前提校验、逆操作和 ID 生成，不把整个 HTTP 请求盲目留到将来重新解释。

同步流程：能力与库身份校验 → 取得固定 NAS 日志上界 → 分页拉取至上界 → 重建本地基线并依序尝试 pending → 传输所需新 blobs → 依序提交 → 持久记录回执 → 再拉取 NAS 正式结果 → 重建可见状态。同步全过程允许 NAS 其他写入；每条接纳都重新在 NAS 写锁内验证前提。

同步使用独立跨进程 `sync.lock` 防止同时发起两次合并；网络等待不持有本地编辑锁。已开始提交但结果不确定的操作直接重试完整原提案，让 NAS 同时核对 ID 与摘要，不能用只有 ID 的状态查询替代内容身份确认。传输层必须明确区分“服务端保证未提交”的拒绝和超时/断线/未知结果，后者保留待确认状态。确定拒绝后刷新 NAS 目录供冲突界面展示；重做先验证新方案和原文件，再追加决定，失败不覆盖原意图。

pending 的原始记录不修改。回执、放弃决定、重做方案和撤销以追加记录表达。冲突时停止后续提交；用户保留 NAS 或重新选择本地结果后，依赖操作必须重新验证。不能在冲突中直接删除队列记录来让后续请求错误通过。

客户端网页请求的幂等键与内容摘要记录在 pending 事件中：有业务操作时与入队同一条事件原子持久化，无修改时追加独立本地请求回执，不发送到 NAS。新请求事件使用 pending payload v2，旧 v1 仍可读取，旧客户端遇到 v2 必须停止而不是忽略回执。重试先检查持久回执，同键不同摘要拒绝；结果引用独立本地意图 ID，在 NAS 接纳、放弃或显式重做后也不改写原请求结果。请求回调最多入队一个操作，过期或跨客户端的作用域拒绝使用；内容准备在进入串行编辑作用域前完成。

网页冲突编辑先读取有效本地前缀，展示原修改前值、当前值与准备提交的值；读取草稿不持久化决定。草稿携带新的同步身份与固定前提，编辑只改变期望值，保存仍经过 Resolve 的完整前提和原件校验。用户查看期间不自动刷新并替换前提；手动刷新才重新构建草稿。响应不确定时复用完整同一草稿重试，不能生成新身份后猜测前次失败。原始操作和替代决定继续追加保存在本地历史。已接入文件/目录及标签重命名、归档盒名称/描述与日期，以及 fileset 配置。日期复用部分精度控件，不补齐未指定的月日。fileset 草稿展示原配置与当前配置，以原本地配置初始化现有拖动列表；整份 before/after 前提保持不变，成员缺失、角色或循环约束继续由 Resolve 验证，不自动逐行拼接。封面冲突展示修改前、当前与本地候选文件，允许选择仍有效的对照候选或清空封面；候选名称和可用性从固定有效前缀读取，已回收或不属于该归档盒的文件不可提交。当前封面引用也作为精确 before 写入新提案，NAS 再次变更后必须重新确认；保存和响应不确定重试沿用同一提案，原意图保持不变。其他封面仍可通过既有文件菜单设置，不把冲突处理扩展成一次全库文件加载。删除范围使用下述专用确认入口；尚未接入的其他动作仍需要各自领域编辑入口，不提供通用 JSON 或“强制覆盖”绕过验证。

NAS 已提交而客户端未收到响应时，按同一个操作 ID 与摘要重试。回执查询早于当前状态冲突检查，避免已经成功且后来被撤销的操作在重试时被重新执行。冲突后的新方案使用新标识并记录与原始意图的关系。

删除冲突编辑覆盖网页生成的 delete_box_contents、delete_entry_contents、delete_fileset_entry。草稿重新调用同一删除快照生成入口，展示原范围和当前范围的名称、文件/子目录数量，并提供当前对象的检查链接。用户必须再次明确确认整个当前范围（可能包含 NAS 新增文件和新标注）才可保存；不自动将新增对象并入旧意图。新方案保存完整当前快照、当前关联组合引用变化以及新的稳定 deletion 前提；查看后再有修改仍拒绝，响应不确定重试使用同一新身份。目标已不存在时不构造空删除或复活对象，只提示保留 NAS 结果。旧删除意图继续可查；替代删除的严格撤销恢复实际确认的完整范围。其他未接入的领域动作继续使用独立编辑器，不能用此入口强制覆盖。

pending 日志复用普通文件日志的校验和、fsync、跨进程锁和末尾断写恢复，但使用独立目录与本地事件序号，不作为 NAS 领域日志重放。入队、开始发送、确定拒绝、确认回执、放弃、重做分别追加记录。开始发送先落盘；网络失败保留“结果未确认”，禁止放弃或修改原意图，直到 NAS 回执或确定未提交的结果消除歧义。仅确定的服务端拒绝可记录为冲突，不能把超时当拒绝。重做保留原意图及原因，使用新 ID，并保留原逻辑排队位置；后续依赖原 ID 的操作不会被偷偷重定向，必须重新验证。任何未解决冲突或失效依赖都阻止越过它提交后续操作。

客户端物化重建在一个 SQLite 事务内先重放已确认前缀，再按逻辑顺序叠加 pending。每个 pending 使用 savepoint，前提失败时撤回该条，提交已确认状态与此前有效修改，并报告阻挡位置；数据库或日志读取失败则整次回滚，保留上一个可用视图。已确认日志中的同步身份优先于本地回执，可识别丢失响应；已取得回执但尚未拉到正式事件的修改继续叠加，避免同步中途消失。视图内的数字位置可能随重建变化，仅供内部索引使用，对外操作必须使用 NAS ID 或 pending 唯一 ID 的明确引用，不能把视图位置当成 NAS ID。新写入和 pending 重建共用状态约束检查，历史重放不追加新约束。

客户端删除预览的 revision 使用状态摘要而非视图数字序号，绑定库与目标身份、完整删除范围、关联 fileset 配置变化，以及该 box 最近操作的稳定身份。未接纳的本地操作使用其同步身份，已接纳的同一操作从 op_sync 取得同一身份，其他 NAS 操作使用正式 ID；仅接纳或重建不应改变该身份。保留 NAS 当前“box 有后续修改则重新确认”的约束，同时校验完整范围，不能因别处的视图序号移动误用旧确认。删除提交在客户端编辑锁内重新计算并核对摘要，随后仍以自足快照 payload 入队；NAS 接纳时继续核对真实当前状态。

删除快照提案采用 SyncProposal v2，新增 deletion 前提（box 与最近操作的稳定身份），能力协商显式声明 deletion_snapshots。旧 v1 提案和摘要保持不变；旧端拒绝 v2，客户端在未声明能力时不提交。原先直接提交完整本地删除快照会因前序本地操作被 NAS 接纳后物化时间变化而与自己冲突，因此删除命令改为：先核对稳定前提，再比较除物化创建/更新时间外的完整语义快照及 fileset 变化，最后从当前状态生成精确删除 payload。真实后续修改（包括改后又改回）因稳定身份不匹配仍冲突。该转换同时用于客户端叠加与 NAS 接纳，发生在 Apply 之前；原始提案、摘要与确认依据不改写，正式事件保存可独立恢复的完整实际快照。不能通过放宽旧 Apply 或删除所有时间比较来实现。

接纳协议 v1 使用独立 SyncProposal，不接收客户端伪造的正式日志行。请求摘要由 NAS 从完整提案计算，包含原始时间、操作、payload、依赖、操作组与撤销引用。时间必须可无损表示为现有纳秒时间；未知协议/操作和传输伪装的 origin=sync 明确拒绝。撤销请求只带目标引用，NAS 从已提交事件计算逆操作；不接受客户端同时指定撤销目标和任意 payload。提取操作必须声明实际读取的文件内容哈希，避免把断网期间旧原文件的提取结果应用到已被替换的版本。

## 4. 操作覆盖与冲突原则

所有现有写 action 都要进入显式同步能力分类，测试对照实际注册表，避免新增 action 默默缺失。下表是策略分类，不替代每个 handler 的实际审查。

| 操作族 | 前提、合并与撤销 |
| --- | --- |
| create_box/create_folder/create_tag/create_saved_search | 保留本地实体 UUID；父对象存在、同名唯一约束满足。相同同步 ID 重试取回执，不能凭同名合并不同身份。 |
| update_box/rename_entry/rename_tag/move_tag/update_saved_search | 校验用户所见 before 及父级、唯一性、循环约束；互不相关字段可按实际 delta 应用，同一字段竞争报冲突。 |
| tag_files/untag_files/tag_boxes/untag_boxes | 按原有来源/拒绝语义应用；对象仍存在，不因删除而复活。保留严格逆操作检查。 |
| import_files/upload_files | 原始实体身份和内容哈希不变；先完整入库 blobs，再提交，路径/替换前提不成立报冲突，不在 NAS 静默重新命名。 |
| extract_metadata/set_metadata | 保留提取事实、版本和 origin；验证原文件内容及原有 metadata 前提，不把过时提取应用到已替换内容。 |
| set_fileset | 完整 before/after 比较，保留成员和主文件引用；页序竞争按配置冲突，不能逐行随意合并。 |
| delete_box/delete_folder/delete_tag/delete_saved_search/delete_files | 检查当前对象、后代和引用约束，不能把 NAS 新增成员一并吞掉；严格撤销恢复所记录身份。 |
| delete_box_contents/delete_entry_contents/delete_fileset_entry | 比较完整删除范围快照及关联配置；NAS 新修改阻止删除，不扩张删除范围。 |
| restore_box_contents/restore_entry_contents/restore_fileset_entry/undo_upload_files | 保留恢复快照；检查当前名称、身份、引用及撤销阻挡条件，失败保留 pending。 |
| request_receipt | 协议产生的幂等结果，不作为用户可编辑领域命令；同步映射与请求回执不能互相冒充。 |

归档盒标签关联的新写入（含 pending 重放和严格撤销）必须断言添加前不存在、移除前存在。原先仅靠命令生成时过滤和 Apply 的幂等增删，在离线与 NAS 同时做相同修改时失效：会生成没有实际变化的正式 op，其逆操作却会撤销另一方的关联。现在在 library 的写前校验中拒绝此类过时意图；相同同步身份已接纳的重试仍优先返回原回执。历史 Apply 保持原样，避免旧日志因新增约束无法重建。不将重复操作静默算作成功，因为现有 payload 的逆操作无法表达“此次实际未改变”。

文件标签的 `untag_files` 同样在新写前断言 payload 指定的来源认领仍存在，不能仅检查聚合后的标签是否存在。重复移除已不存在的来源会形成可撤销的空修改；其他来源仍保留标签也不满足此前提。移除一个来源、撤销恢复该来源均不改其他认领。`tag_files` 的同来源重复添加已有唯一约束保护；旧日志重放仍保留原 Apply 行为。

提取结果的新写还需逐文件断言 `file_extractions` 的当前版本等于 payload 的 `PreviousVersion`（不存在为 0），包括接纳、pending 和严格撤销。原先只验证字段、拍摄时间及内容哈希，当新版本恰好没有改变字段时无法发现竞争，旧离线操作及其逆操作会回退另一方的提取版本。此校验放在 library 新写路径，旧日志仍按既有 Apply 重建；逆操作本来就交换 Version/PreviousVersion，因此不新增字段、不改变已记录提取事实。

离线删除标签后，NAS 新增子标签或使用该标签会触发既有 `ErrTagInUse`。在同步接纳与 pending 重放中，此类状态变化归为可解决冲突：保留原意图、阻止后续提交，允许保留 NAS 结果后继续。普通删除标签的“仍在使用”约束不变；不能把这个领域拒绝当作导致整个客户端状态不可读取的重建故障。

撤销引用以“NAS 正式 ID”或“本地操作唯一 ID”显式区分。NAS 接纳前把本地引用解析到已确认正式 ID；不靠本地数字巧合匹配。撤销/操作组关系进入正式日志，重建仍可得到同样历史。未知 action 或协议版本明确拒绝。

本地历史对 pending 和 accepted 的撤销事件也提供现有“撤销”确认入口，从而允许离线重做；它仍提交对该事件独立本地 ID 的逆操作，不跳过严格前提或修改旧事件。awaiting_receipt、conflict、discarded、replaced 不提供该入口，避免对结果未明的提交作决定。

本地操作列表随当前分页返回展示摘要，复用正式历史的代表名称、批量数量、改名前后名称与当前名称标记。pending 队列读取本已包含原始提案，因此只解析当前页，不为每行额外请求详情、反复重建叠加视图，也不向列表传输完整 payload。原提案内的名称优先，撤销不伪装成其反向动作摘要；解析当前名称时使用同一已加锁视图的事务。该展示字段不落盘、不建立索引，不改变 NAS 正式历史按可见行加载摘要的机制。

## 5. 缓存与传输

缓存区分元数据、预览和原文件；API 返回未缓存与真正读取/校验失败的不同状态。自动按需下载可中断和重试。离线目录与搜索使用明确的元数据同步状态，不把“未获取”当“不存在”。网页资源随本地二进制提供，远程地图等非必要外部资源离线时明确降级。

客户端配置 max_age 与 max_bytes；年龄基于最近访问，超龄逐出、超额按 LRU 逐出。容量包含显式保留项，但保留项不可自动清除，超过上限时提示调整。未上传内容与 pending 所需内容单独统计，不能淘汰。正在使用/传输的内容受租用保护；下载前预算，下载中限制实际体积，临时文件也计入管理，不能无限写入后再清理。

缓存对象位于 `cache/objects/`，原文件地址对应 `.data` 和可重建的 `.json` 进度/访问记录；未完成下载按“实际字节 + 剩余预留”占用容量，避免并发传输共同超额。`cache-pins.json` 位于可逐出缓存之外，以离线选择 owner 记录成员集合；多个选择共享文件时，删除其中一个选择不撤销另一个的保留。降低配额不删除受保护内容，返回超额状态。

每个对象的内核共享锁保护读取，独占锁保护下载和删除；全局缓存锁只保护短暂的配额/索引决策。清理持有全局锁后只尝试对象锁，遇到活跃读取或传输立即跳过，不等待，不与对象持有者反向死锁。进程退出由内核释放租用，不依赖 PID 存活猜测。锁文件始终保留；不能通过删除锁文件“解除”租用。缓存索引缺失或损坏时先报告恢复需求，不能把未知占用当零字节继续下载。

缓存下载从已知目录事实取得原文件大小，验证 NAS 库身份后按 Range 续传；字节 fsync 后才持久化确认偏移。恢复时截断超出确认偏移的尾部。完整大小及 SHA-256 校验通过后才标记 complete；校验失败显式报告并重置该次可丢弃传输，保留选择和 local-blobs 不受影响。读取完整缓存时再次核对内容并持有共享租用，关闭时更新最近访问；缺少或未完成的缓存返回 not_cached，实际字节错误返回 blob_integrity_mismatch。

缓存索引重建从完整历史/待同步视图中的内容事实取得预期大小，逐对象核对缓存文件；长时间哈希只持对象独占锁，不占全局配额锁。丢失或损坏的记录可重建，未知格式版本拒绝覆盖；活跃对象计入 skipped。部分传输保留确认偏移，校验失败内容标记 corrupt，不能标成已缓存可用；缺少缓存数据则移除失效记录但保留离线选择。显式重新下载可丢弃 corrupt 字节，避免超额坏文件阻挡自身修复。此恢复路径不扫描或修改 pending/local-blobs。

按哈希复用内容；续传核对前缀与最终整文件哈希，原子安装、fsync 后才允许 NAS 接纳引用。同步确认以 NAS 持久回执为准。fileset 离线准备递归收集实际预览依赖，循环损坏终止，未全部准备完不标“已离线”。缓存索引损坏可从缓存文件与持久保留清单恢复；恢复后不得误删唯一的 pending 内容。

缓存恢复补充：原方案要求每份字节都能在原件目录或派生映射中找到大小；派生映射丢失时，这会使仍完整的预览无法重建计量，故显式 cache rebuild 改为先移除格式损坏的可丢弃映射（仅元数据，保留字节），未来版本和 I/O 错误仍拒绝处理。没有目录/映射事实时，优先沿用有效缓存记录的大小与确认偏移；连记录也丢失时，只有全文件 SHA-256 与地址一致才可恢复为完整字节，否则记录为损坏、不可续传，实际占用仍计入配额。此过程不猜测原件与配方的关联、不创建领域事实，缺映射的预览仍为未缓存；重新准备取得可信描述后可复用已验证字节。既有原件事实仍优先，原件与 pending 保护不变；活跃字节租约继续跳过。不选择按实际长度直接宣称完整，也不将未知占用当零字节跳过配额。

离线选择保存逻辑文件 ID 和 fileset ID，而不是把首次展开的内容地址永久当作选择。每次准备或查询就绪状态均以当前客户端视图重新展开：包含配置中的全部角色成员、嵌套组合和独立指定的主文件；同目录未参与配置的文件不自动加入，可单独选择。内容按地址去重，仍保留对应文件身份。解析缺失目标或循环时明确失败，不能将不完整结果作为成功的离线清单；依赖解析成功本身不表示字节已可用。保留清单和下载状态分开，就绪判断须核对当前依赖全部可读，并说明依据的目录同步边界。

离线准备按文件当前的名称与媒体事实，从共享预览规则表展开缩略图和详情预览配方；该规则表同时生成网页使用的类型选择，避免前后端依赖分叉。相同内容的不同文件取所需配方的并集，同一内容/配方仅准备一次；原图、PDF、文本等直接读取原件的详情不额外生成无用预览。就绪状态分别列出原件与预览可用数，只有两者全部可读才为 ready。准备优先使用本地原件转换，必要时获取 NAS 派生内容；远端排队可取消等待，终止失败不会无限重新请求。准备结束重新展开当前选择，不能把下载开始时的旧依赖当成最终就绪依据。这些缓存操作不修改归档历史。

缓存逐出（包括为下载腾出容量）先持客户端编辑锁，再持缓存锁，按当前视图刷新逻辑选择的内容保留集合，直到逐出决定完成才释放；网络等待不持这两个锁。逐出对对象锁仍仅非阻塞尝试，避免与已持对象锁的下载形成反向等待。目标被删除而无法完整解析时保留该选择原有内容集合，等待用户更正或取消；不因失效目标静默清除离线保留。此处刷新是删除字节前的安全检查，不引入每次编辑后必须另写一份索引的持久化依赖。

NAS 原文件传输复用已有分块暂存内核，但使用独立 `sync-uploads/`，不与网页上传目的地或提交回执混用。会话由原文件地址确定，可重复创建、查询偏移和校验已传前缀；每块继续遵守写入、fsync、进度持久化后确认的顺序。完成时由 library 校验完整大小与 SHA-256 并安装到 blobs，再标记暂存可清理，不伪造正式 op。完成响应丢失时客户端先探测已落盘原文件。下载支持 Range 和内容地址 ETag，接收端仍须校验完整文件后发布缓存。哈希碰撞导致 NAS 分配不同地址时报告冲突，不能为了匹配远端地址覆盖 NAS 内容。

确认后的本地原文件在最终目录拉取完成后转入缓存：资格只由已验证正式日志前缀中的 blob 引用证明，不能仅凭 HTTP 成功、临时视图或未持久回执。仍被 active pending 引用的原文件保持受保护；有未解决撤销依赖时本轮不迁移。准备导入持跨进程共享租约，读取原文件持对应对象共享租约，迁移只尝试独占租约，遇到活跃使用跳过，不等待形成反向锁依赖。新导入仍通过原有 placement 锁原子安装。 手动清理缓存和修改缓存上限时也重试这一迁移，避免同步时因活跃读取被跳过的已确认内容永久留在缓存配额之外；仍采用相同正式前缀、pending 引用与租约校验，不强制移动活跃对象。

迁移先核对本地内容，再记录未完成缓存状态、同盘重命名并 fsync 两侧目录，最后标记缓存完整；不复制大文件、不触碰 NAS 原文件。中断后的缓存字节可通过既有缓存重建恢复。迁移本身不增加磁盘字节，完成后按当前配额/LRU 清理；明确离线保留项计入体积且不可自动逐出，超限可见。没有正式 NAS 引用的准备残留和未同步原件继续保留，不能把未知内容当缓存清掉。此生命周期仅作用于客户端副本，不改变 NAS 永久历史与原文件承诺。

对已标记损坏的缓存显式重试时，在对象独占租约及缓存锁内移除坏字节和旧预留记录并 fsync，再按可信原件事实或派生描述重新申请完整预算。原方案先比较旧大小再清空，无法修复映射/索引均丢失后只按实际坏字节长度重建的记录；旧预留还可能使过大的坏文件阻挡自身修复。仅损坏缓存允许此重置，正常记录仍拒绝大小不一致；未同步原件及离线选择不受影响，新的预算不足仍明确失败。

派生预览传输通过 `derived_previews` 能力单独协商；未支持时只拒绝该功能，不影响原有元数据/原件同步。NAS 使用原文件内容地址与已有 recipe 注册表定位任务，不依赖文件仍处于当前目录，保留历史原件仍可生成预览。同步描述包含任务 generation、输出 SHA-256 与大小；下载继续鉴权，Range 的 ETag 绑定输出内容，generation 或输出变化时拒绝旧请求，不拼接不同版本。

客户端派生字节存入与原件相同的内容寻址缓存，共享配额预留、分块 fsync、校验、读取租约和 LRU。`cache/derived/` 保存可丢弃的原件/配方到输出描述的映射及已见输出大小，用于索引重建；不写 NAS op 或客户端 pending。输出换代时保留旧输出事实供尚未逐出的字节计数和校验，原件已明确保留离线时其当前预览输出也受保护。读取已缓存预览不访问 NAS，缺少映射或字节时返回未缓存；实际坏字节仍报告校验错误。尚未完成的远端任务不隐藏客户端已有的可用预览。传输缓存与网页队列不代表本地生成或完整离线预览准备已完成，验收状态见实施记录。

客户端网页媒体接口复用 NAS 的状态/请求/取消/Range 契约，后台协调器单独使用 `cache/media-jobs/` 与跨进程 state/worker 锁。任务身份绑定原件哈希与配方；请求只排队，不在 HTTP 生命周期内下载。后继 worker 可恢复 running 任务，取消更换 generation 并中止在途传输，旧任务不得覆盖新请求。状态轮询检查映射、缓存记录和实际大小，不重复哈希大视频；实际读取仍完整校验并持有租约。已缓存内容不读取连接凭据、不访问 NAS；逐出后回到 missing，网络/配额失败使用客户端语义提示。损坏的可丢弃队列记录可重新请求，不影响 pending 或归档历史。本地生成与完整离线准备依赖仍须单独完成并验收。


本地转换的临时目录放在 `cache/workspaces/`，通过独立 OS 租约和持久预算记录加入同一缓存配额。先完成准入再写临时文件，整个目录树的实际字节计入 partial，未使用的预留计入 reserved；不把中间文件当成已缓存的可读预览。活跃租约不因 TTL、降低配额或其他进程清理而被删除，降低上限时显示超额。扫描只能非阻塞取得已失效工作目录的租约后清理，包括创建中断或预算记录损坏的残留；不能凭 PID 或经过时间猜测任务失效。转换期间监测整个临时目录，结束后再次检查上限，超过预算取消并拒绝发布；外部工具短暂超写的实际字节仍完整计数。本地转换使用共享工作目录租约；清理尝试独占租约，以确保其他转换进程仍持有它时不会删除目录。

`client serve` 为本地预览启动当前二进制的专用 `client render-worker` 子进程，只传客户端目录、工作目录 ID、原件哈希和配方，不传 NAS 凭据或任意输出路径。工作进程重新验证这些身份，独立持有原件读取租约与工作目录共享租约，并运行现有转换器。主服务通过保持打开的输入管道表达生命周期；取消或主服务退出令管道 EOF，工作进程取消转换、等待工具退出后才释放租约。取消不直接抢先杀死监督进程；待完整端到端故障矩阵验证其边界。

仅靠上述 EOF 协议不能覆盖监督 worker 自身崩溃，尤其 Windows 上不应依靠父进程逐个猜测后代 PID。Windows 客户端在发送渲染请求前，将新 worker 加入不允许 breakaway 的内核 Job Object，并启用 `KILL_ON_JOB_CLOSE`；该 Job 的句柄仅由请求方持有，不继承给后代。接纳进 Job 失败则不发送任务，停止新 worker 并报错。主服务退出会关闭 Job，工作进程正常或异常退出后，请求方终止 Job 中残留后代并等待 ActiveProcesses 归零，再返回并释放原件/工作目录租约。保留原 EOF 协议供正常取消使用，Job 是进程树故障边界，不是通用任务平台。Unix 改为在启动 worker 时创建独立进程组，并在发送任务前验证它确实是组长；后代继承该组。工作进程 stdout 关闭后，请求方在尚未 Wait/reap 组长时向整个组发出终止信号，避免对可复用 PID 发信号；随后回收组长并等待内核报告组不存在，才释放原件/工作目录租约。作为 init/subreaper 运行时仅回收该组被收养的后代，不等待其他任务组。macOS 对纯僵尸进程组可返回 EPERM，不能把它当作退出依据，继续等 ESRCH；Wait 后不再发送新的终止信号。Office 转换在该专用上下文中继承 worker 组，取消时终止整个组；普通 NAS 转换仍保留原先独立工具组。此机制针对受控转换工具，不是阻止任意程序主动 setsid 脱离的安全沙箱。语义依据 [setpgid](https://man7.org/linux/man-pages/man2/setpgid.2.html) 与 [waitpid](https://man7.org/linux/man-pages/man2/waitpid.2.html)；正常取消、主服务退出、worker 强杀和两层后代分别验收，不用编译成功代替平台运行证据。

本地产物在转换进程结束后核对大小与 SHA-256、fsync，先持久化可重建映射与未完成缓存记录，再在输出对象独占租约下同盘移动、fsync 目录并标完整，最后在同一缓存临界区释放临时预留。原件租约在取得输出独占租约前关闭，允许产物与原件具有相同哈希而不自锁。失败保留未同步原件与 pending，不追加归档操作。网页优先使用本地原件生成预览，本地转换工具不足时仍可获取 NAS 预览；已缓存结果不访问 NAS。普通图片按目标尺寸估计临时预算，其他转换按保守上限准入；空间受保护内容占用时只使用可用余额，实际超额仍拒绝发布。

## 6. 授权与边界

NAS 显式启用同步凭据，客户端绑定库 UUID。网络同步端点使用独立认证，不能把现有局域网网页的无登录假设扩散到同步授权。凭据保存在运行配置中，限制文件权限，不进入事件历史、错误响应或日志。支持撤销凭据，协议协商包括信封版本及允许的操作集合。

NAS 管理入口为 `kist --library NAS sync-access create|list|revoke ID`：创建时仅输出一次随机 Bearer 密钥，列表只显示凭据 ID 和创建时间。`sync-access.json` 原子持久化 SHA-256 摘要，POSIX 权限 0600；每次请求重新读取，其他进程撤销后新请求立即失效。它是运行授权配置，不是归档事实，不写 op，也不被归档撤销恢复。没有配置时全部同步请求拒绝。现有普通网页 API 的局域网访问策略保持原契约。

`/api/v1/sync/` 端点在读取请求体前校验凭据；仍执行现有 Host、Origin 和 Fetch Metadata 检查。能力、固定历史分页和提案提交有 OpenAPI 契约。提交响应显式区分成功回执、确定拒绝和提交结果不确定；日志可能已落盘的 WriteOutcomeError 不标成拒绝，代理错误或连接断开也不能被客户端当作确定拒绝。

客户端传输适配器不持久化状态，只实现 library 的 SyncPeer 边界。每次提交只认可完整、内部一致的回执或明确拒绝信封；非 200 响应、截断 JSON 和重定向保留不确定语义。禁止跟随重定向以避免凭据转发。连接默认要求 HTTPS，回环地址允许 HTTP，其他明文连接必须显式配置。长时间原文件校验由操作 context 取消，不用短响应头超时迫使大文件反复从头校验。

命令入口采用 `kist client init|connect|sync|status DIRECTORY`，客户端目录必须显式给出，不复用默认 NAS `--library` 位置。init/connect 从标准输入读取凭据，先认证并验证协议能力，再保存连接。`connection.json` 独立保存版本、绑定库 UUID、URL、明文许可与凭据，原子替换且 POSIX 权限 0600；不是归档事实，不进入 op 或重建索引。连接可以轮换凭据和地址，但不能更换绑定库 UUID。状态输出只含非敏感连接信息、已确认目录边界与待同步操作；不联网，跨进程更新后重新读取。

首次元数据复制固定日志上界，以已提交日志为源；不复制 SQLite，也不复制运行中不一致的目录树。主库写操作仍由 library 完成，所有同步判定在生成/接纳层完成，Apply 不访问网络、时钟或配置。

分页边界包含库 UUID、截止 op ID 和该事件校验和；各页在提交锁内确认边界仍匹配，再返回已验证的原日志信封。后续 NAS 写入不改变本次前缀。单页限制记录数与目标字节数，但旧的单个大事件必须整体传输，因此允许其独占一页并超过目标字节数，不能截断事件或重写校验和。当前先复用日志迭代验证；每页需要扫描固定前缀，后续如实测成为瓶颈再增加可重建的定位索引。

## 7. 既有方案的替换与验证

3.12 原先预留将 NAS op ID 扩成 (instance_id, seq)。本场景有唯一 NAS 权威，不需要多主排序：保留 NAS int64 顺序，独立本地标识映射足够。旧预留不是已实现协议，不据此改变历史 ID。

旧 origin=sync 预留混合传输方式与执行性质，无法保留 extractor 语义，故不采用。旧全量库复制适用于停止写入后的备份，不适用于可写 NAS 的部分缓存客户端；不弱化备份保证来迁就新功能。

分阶段验证：日志 v1/v2 兼容与 v3 信封 → 同步索引普通写入/追赶/rebuild/snapshot/deep verify → 客户端 pending 与缓存恢复 → 各 action patch 与撤销 → 传输中断和幂等 → 真实本地网页离线验收。每阶段检查通过后提交并跟进 CI；最终按 Goal 文件逐项审计。此阶段不发布版本。

### 离线客户端入口与同步文案（2026-10-22）

客户端入口与全部文件、归档盒、回收站、操作历史并列，复用主导航的图标、字号与间距。原先放在显示设置旁的页脚小入口不足以表达日常使用频率，移除该安排；仍复用现有客户端面板，不改变同步协议。同步按钮明确为「与 NAS 同步」，说明同时获取 NAS 变更与提交本地修改，冲突暂停处理；原件与预览的按需缓存、保留离线准备单独说明，不把目录同步完成等同于内容已离线可用。

### 浏览时按需缓存与连接状态（2026-10-24）

客户端网页侧栏显示经过认证、库身份与协议校验的远端连接状态，前台每 30 秒探测；配置了地址不等于已连接，凭据失效和库不匹配单独提示。探测不触发目录同步或提交本地操作。

原先原件读取和元数据提取只检查本地缓存，导致远端可达时仍要求用户手动准备离线内容；现改为缓存未命中时按内容地址获取并校验，成功后继续读取或提取。历史原件同样按历史内容地址获取。网络下载不占客户端编辑或历史视图锁，沿用现有续传、配额和逐出规则；未连接时仍报告未缓存，不报告原文件丢失。元数据尚未提取时，预览规则允许以常见扩展名选择配方，实际内容仍由解码器与内容嗅探验证。预览沿用派生缓存队列，连接恢复后自动重试因未缓存而阻塞的可见预览，每次成功探测最多重试一次。
