# 图片方向校正

2026-10-27 用户授权实现，并确认独立的自动方向开关，同时在 OCR／描述前补齐方向。自动开关只处理启用后新增的图片；已有图片提供显式补全，复用 AI 的暂停、失败与明确重试机制。

## 权威结果与共享输入

原始 blob 永不旋转或重编码。方向是文件 metadata，使用现有 `extract_metadata` action 和 `orientation` 来源，保存相对容器自身 EXIF／HEIF 变换后的顺时针 0／90／180／270 度、原文件校验值、带服务商前缀的模型、配方、判断方式与自报分数。人工覆盖通过既有 `set_metadata` action 写 user 来源；AI 不覆盖人工方向。恢复自动管理是显式清除人工覆盖并重新判断，不把人工设置 0 度当作缺失。

没有新 action 或 schema：现有 handler、inverse、targets、严格撤销、op 索引、同步、snapshot、rebuild 与深度检查承载方向事实。方向不改变文件内容和 captured_at；只在 library 生成并提交 payload，Apply 不判断方向。结果绑定原始 blob；内容不匹配、缺失或无效值均不能应用旧角度。OCR／描述提交继续检查完整 metadata 快照，拒绝方向在推理过程中发生变化的过时结果。

相机 EXIF／HEIF 变换先应用，AI 与人工方向随后应用；缩略图、浏览与 AI 输入使用相同顺序。JPEG／PNG／静态 WebP 和单张 HEIC／HEIF 沿用已有 AI 输入范围。OCR／描述使用完整像素，不使用缩小后的方向判断图。旋转输入优先编码为 PNG；超过 20 MiB 时改用质量 95 的 JPEG，仍保留全部像素尺寸；仍超过限制则报错，不静默缩小。提示词独立于提供方，仍由设置中的模型和 AI 专用代理执行。

## 判断策略

先将整图长边限制到 1024，生成四个方向候选，随机排列并用 A／B／C／D 标记；只让模型选已经正向的版本或 uncertain，代码负责映射角度。推理 low，图片 original。字段严格校验，分数低于 0.9 或无方向证据采用 0；该分数不是正确率保证。

首轮没有可靠方向、但有主文字方向证据时，允许用四象限中心与整图中心的 768 原始像素裁片补充判断，小图不加裁片。至少两个不同象限一致且没有有效票冲突才采纳；中心只作冲突检查。普通场景或没有文字证据时保留 0，不让孤立背景文字覆盖整图主体。网络或协议错误是失败，显式重试，不把错误保存为成功的 0 度。OCR／描述补齐方向时也使用同一持久队列与进程间工作锁；失败、中断或暂停不能被另一个依赖任务绕过重发。

## 派生图片

角度进入图片派生配方标识，同一 blob 的不同方向分别缓存，支持 NAS、离线客户端本地生成与派生同步。旧任务只能发布其自身配方，不能覆盖新方向；撤销方向后可复用先前缓存。原图下载仍返回原始字节。浏览器原生图片详情保留完整分辨率；有校正时使用等分辨率无损派生图片，避免用 2048 JPEG 降低原有清晰度。没有方向变化的图片继续原图浏览。

## 界面与验收

设置复用现有 AI 模型、自动开关与任务队列区块。文件详情的方向模块提供判断／重新判断；人工四方向覆盖与恢复自动管理位于图片浏览页的「更多操作 → 调整方向」，不与元数据标题栏的重提取入口混放。已有 OCR／描述正文不因方向修改而自动重写，后续显式重提取使用新方向。

验证需涵盖 EXIF 与 AI 旋转叠加、HEIF 变换、全分辨率保留、低分／冲突／坏响应、方向复用与人工保护、请求中途变更、撤销／rebuild／snapshot／深度校验、派生缓存隔离及客户端兼容。所有测试素材采用合成图；私人实验图和模型原文不得进入 Git 或 CI。
