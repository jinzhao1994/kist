# AI 代理、账户与功能分层

- 日期：2026-10-31
- 状态：三层配置、独立路由与转录已实现，已完成集成及视觉验收；不涉及发布。

## 目标及替代方案

配置分三层：零到多个代理、零到多个 AI 账户、按功能独立选择账户与模型参数。相同类型可有多个对象，代理和账户各自拥有自动分配的稳定编号及在同类列表内唯一的用户 ID。编号单调增长、不因删除或重排而复用；引用使用编号，改名不破坏关系。ID 支持中文，不作为 TOML 路径或文件路径。

旧配置只有 `ai` 凭据与 `ai_options` 的公共模型／代理，无法表达多账户和独立功能路由，因此不再作为最终模型。实施保留旧格式读取，迁移在配置锁下原子完成；不删除归档 metadata，也不重新调用模型。旧连接迁入第一个 ChatGPT 账户，非空代理迁入第一个 HTTP 代理，原有功能选择继承原模型及自动启用边界。无连接的实例允许空账户列表；不能因启动而登录或探测外部服务。

## 配置与凭据

代理列表提供按需“测试”，仅测试已保存且当前未修改的配置，新建或修改后先统一保存。测试由服务端复用同一 HTTP(S)／SOCKS／Trojan 传输访问固定的 `https://ipwho.is/`，只请求出口 IP、国家／地区和城市，不发送账户、归档文件或 metadata。失败不回退直连、不跟随重定向，整体超时 15 秒，响应上限 16 KiB。IP 位置仅供参考；耗时为完整查询请求耗时，不表示纯网络延迟。服务文档见 [IPWho.is API](https://ipwhois.io/documentation)，选择其免密钥 HTTPS 查询，免费额度目前为每个出口 IP 每天 1,000 次，不保证可用性。

`POST /ai/proxies/{number}/test` 沿用本机 AI 管理接口边界，读取一次已保存的代理（包含服务端保留的认证），不改配置、不入队、不写归档或运行库。诊断结果包含出口、粗略位置、耗时及封闭的失败原因；外部响应和传输错误不原样返回，避免回显代理认证。结果仅在当前页面展示，重新加载、修改代理或保存新修订后失效；请求取消和组件卸载不留下旧结果。页面加载、保存和悬停均不触发测试。服务限流与无效响应独立于代理连接失败展示，不把查询服务故障当作代理配置必然有误。

新配置集中在 `ai_services`：`proxies`、`accounts`、`features`，以及两个编号分配高水位。账户类型为 `chatgpt` 和 `openai`（API Key）；代理类型为 `http` 和 `trojan`。`http` 表示外部 HTTP(S)／兼容现有 SOCKS URL；`trojan` 实现标准 TLS/TCP CONNECT，验证证书，可指定 TLS server name。没有选择代理代表直连，不受进程环境代理意外影响。Trojan 的 WebSocket、mux 和 UDP 扩展不在首版范围；不把扩展字段假装成已支持。

不直接嵌入 trojan-go：其仓库使用 GPL-3.0，项目当前为 Apache-2.0；标准 Trojan TCP 协议很小，独立按公开协议实现即可，避免引入整个代理程序、监听端口及进程管理。参考：[Trojan 协议](https://trojan-gfw.github.io/trojan/protocol)、[trojan-go LICENSE](https://github.com/p4gefau1t/trojan-go/blob/master/LICENSE)。不复制该项目代码。

代理密码、HTTP URL 中的认证信息、API Key、OAuth access／refresh／ID token 都是实例秘密。API 读取只返回脱敏配置和已配置状态，修改时用专用秘密输入；空白表示保留，显式清除／删除操作才移除秘密。编辑对象类型不能继承另一类型的秘密。配置修改沿用统一设置页的保存、修订校验、字段附近报错与未保存跳转保护，一次原子写入。账户登录改为下述临时授权草稿，随页面统一保存；断开已保存连接保留即时操作，并发检查仍按账户编号定位。

删除仍被引用的代理或账户必须返回对应字段错误，用户先调整引用；不静默改走其他账户或直连。后台任务只在开始时解析一次配置及账户，运行中的请求不被设置变更改路。后续任务使用新配置。凭据刷新写入对应账户，不覆盖其他账户或未保存草稿；配置锁不能覆盖耗时的提取调用。

## 功能层

账户列表提供按需“测试”，通过 `POST /ai/accounts/{number}/test` 读取已保存账户的模型目录，沿用账户指定的代理或直连及现有 ChatGPT 刷新路径。15 秒整体超时，不执行推理、不发送归档文件、不产生后台任务；OAuth 必要刷新仍按既有锁与 CAS 更新实例凭据，诊断结果不持久化。接口仅返回全部模型 ID、耗时和封闭的错误分类，不回显密钥及服务端错误正文。新建或更改账户／代理后先统一保存，未配置或待登录时禁用测试，不自动测试或轮询；与代理测试共用前端生命周期和提示样式。

测试结果仅显示结论、模型数量和请求耗时。最初按用户预期在第二行列出全部模型 ID，但实际目录可达 130 项，过度撑高表格，因此移除该展示。OpenAI API 的本机密钥存在状态显示“已配置”，测试失败不清除凭据、不假装已经断开；仅成功读取目录也不代表余额充足或每个模型都可调用。认证失败、目录权限不足、限流、连接失败与超时分别说明。模型目录协议参考 [OpenAI API](https://developers.openai.com/api/reference/resources/models/methods/list)。

独立配置方向、OCR、描述、结构化提取和语音转文字：账户编号、模型、推理强度、图片 detail，以及各功能自动开关及启用后 op 边界。不是所有接口都接受所有参数；语音转文字不发送图片 detail／推理参数。未配置的功能不阻碍其他功能，也不隐式使用列表第一个账户。描述／OCR／结构化输入需要方向前置时使用方向功能自己的账户与模型，不能沿用调用者模型。

OpenAI API Key 使用官方 Bearer 认证、`/v1/models` 的 `data` 列表、Responses 和 `/v1/audio/transcriptions`；ChatGPT 的现有登录协议与模型目录响应保持独立适配。参数由共享契约传递，不复制提示词。服务商错误不得回显密钥或原始请求。

语音转文字接入现有提取任务与人工保护机制，保存为独立 metadata 命名空间，支持单个文件、重新提取、自动处理新增文件、已有文件补全、暂停／明确重试。先支持官方可接受且不超过上传限制的音频文件；超限必须明确失败，不截断录音、不静默漏掉后半段。视频提取音轨和超长音频分段不在此次必需范围。模型支持可手动填写，不能用图片模型目录假设语音能力。

## 转录后端阶段（2026-10-31）

已新增 `transcription` 持久提取队列、单文件提取／重提取／补全／暂停／重试接口，并加入共用串行调度器。新任务采用自身功能账户和模型；旧单账户配置不会自动开启转录。当前文件识别支持可检测为音频且具有受支持扩展名的输入，包含 WAV、MP3、FLAC、M4A；未识别的容器、视频及超过 25 MB 的原文件明确拒绝，不截断输入。FLAC 和 M4A 的字节识别补入共用媒体检测器。

输出为 `transcription:text`（256 KiB 上限）、`hint`、`model` 和 `recipe`，不另存输入。复用普通 metadata 操作、快照并发检查、人工编辑保护与归档重建；不会改文件描述或拍摄时间。生成的静音 WAV 验证了队列新文件边界、去重、失败暂停／明确重试、人工正文不被覆盖、长文本拒绝和 `rebuild`／`verify --deep`。没有真实语音上传。

本阶段测试发现手动请求和批量补全仍检查旧全局模型，现统一由功能配置检查，新增回归断言防止仅配置独立模型时被误拒绝。新功能尚待设置页、详情元数据入口、翻译和视觉验收，不对用户宣称已完整可用。

## 刷新并发收尾（2026-10-31）

审查发现仅用配置 CAS 不能阻止两个请求同时兑换旋转 refresh token：后写入者虽被拒绝，远端仍可能因重复兑换使会话失效。现使用按稳定账户编号命名的 OS 锁，最多等待一分钟并接受请求取消；拿到锁后重读最新凭据，复用已经刷新完成的 token，验证登录身份未改变，再刷新及 CAS 保存。远端请求期间不持全局配置锁。旧单账户调用和新模型目录共用该路径；迁移前保留环境代理继承，显式迁移后按直连规则执行。

本机并发测试覆盖旧／新格式同账户只兑换一次、另一个账户配置不被慢刷新阻塞、等待取消、刷新期间断开不复活凭据、同编号改为另一身份不被任务沿用。相关账户／API／配置／AI／提取回归 race 测试及静态检查通过。README 和实例设置说明同步三层配置、转录及当前完整文档边界。

## 调用边界复核（2026-10-31）

## 登录草稿与空闲续期（2026-10-31）

原先授权回调直接写入已保存账户，迫使用户先保存再登录；这不满足新建表单里完成登录、全页统一保存的交互。现将设置页登录改为服务端内存中的临时授权事务：接收当前账户及代理草稿，沿用相同的代理秘密保留、编号解析和格式检查，不发布配置、不分配正式编号。新代理的路线可直接用于 OAuth。前端仅持随机能力引用、登录结果和邮箱，不接收 access／refresh／ID token，不写浏览器持久存储。

`POST /ai/sign-ins` 开始授权，`GET /ai/sign-ins/{id}` 仅查询该事务，`DELETE` 取消并清理；没有列举能力引用的入口。授权沿用 PKCE、state、nonce、签名及身份校验。进行中的授权仍最多等待 10 分钟；整个草稿从发起起保留 30 分钟，取消新建、取消编辑中新增的登录、删除条目、放弃／重新加载或离开设置页时清理。关闭页面的清理是尽力而为，服务端过期计时兜底；服务重启丢弃草稿，需要重新登录，已经保存的凭据不受影响。内存事务是有意的短期秘密状态，不新增 JSON、runtime.db 秘密表或第二份正式配置。

统一保存时，在同一个配置原子写入中解析能力引用并写入凭据，仍检查完整配置修订。能力必须属于同一临时／正式账户编号、已经成功授权、未取消和未过期，且不能用于 API 账户、显式清除或重复消费。失败的字段校验不消费草稿；成功保存才移除临时凭据。保存与取消／过期由同一短锁确定顺序，不能在已取消后复活授权。拒绝了“登录后立即保存账户及代理”的方案，因为它会让放弃修改无法撤回账户创建；也不让前端保管 token，因为真正的 AI 调用及续期均在服务端。

账户行将连接相关操作放在左侧，固定以“测试、编辑、删除”收尾，与代理行保持共同操作顺序。ChatGPT 已有登录凭据时将“登录”明确标为“重新登录”，用于重新授权，避免与“断开连接”同时出现时含义不明；未配置时仍显示“登录”。统一用“已配置／未配置”表达是否有凭据；未配置用灰色，授权和测试失败用现有红色错误样式。新建表单可直接登录；成功后明确提示仍需保存。临时账户在正式保存前不执行模型测试或提取任务。旧的按正式编号即时登录接口保留兼容，设置 UI 不再使用它。

服务生命周期增加独立的凭据维护循环，每分钟检查已保存 ChatGPT 账户，在 access token 接近过期时沿所选代理续期，不执行推理／模型查询，不依赖页面、不受各提取队列的暂停影响。复用按账户的跨进程 OS 锁、重读及 CAS，保存最新旋转 refresh token；远端请求不持全局配置锁。API Key 和空账户不参与。临时网络／服务错误按 1、2、4 分钟至最多 1 小时退避；确认 refresh token 失效后停止重复尝试，设置行提示重新登录。失败只保存可丢弃的内存重试状态并绑定凭据指纹，其他进程更新凭据后旧状态失效，不清空配置中的凭据。后台刷新仍属于独立配置写入，若与打开中的设置修订冲突，沿用现有修订冲突提示，不覆盖草稿。

## 自动处理布局与失败策略（2026-10-31）

各 AI 功能与 GPS 一致，先展示新增文件的自动处理开关，再展示连接和推理参数。支持思考强度的功能将账户、模型、思考强度放在同一行，图像精度独占半宽下一行；窄屏按相同顺序折为单列。语音转文字没有图像参数或思考强度，保持账户、模型两列。使用共享字段布局，不为单个功能复制样式。

原先 GPS 的失败暂停可配置，而 AI 固定失败后暂停。现每个 AI 功能使用 `ai_services.features.<name>.pause_on_error`，缺省为 true，保持已有默认行为；显式 false 允许继续处理后续任务，失败项仍需明确重试。独立方向任务和其他提取的前置方向判断遵循相同策略，不因由另一功能触发而绕过设置。该选项只控制失败是否触发暂停，不会解除用户已有暂停，不影响其他功能。设置仍随整页统一保存，支持清除显式值以跟随默认。GPS 沿用自己的 `geocoding.pause_on_error`，采用相同标题与说明，不改变服务冷却和请求间隔。

图像精度是发给模型服务的 detail 参数，不控制本机缩放。方向判断仍采用既有全图最长边 1024 像素、必要时最多 5 个局部区域且每个最大 768×768 像素的固定策略；此轮不增加尺寸配置。OCR、描述及结构化提取保留完整像素尺寸，旋转和 HEIC 转换可能重新编码，不应把完整像素等同原始文件字节。
