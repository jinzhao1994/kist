# 跨客户端修改后的目录刷新

## 问题与实现

文件列表为保留返回位置，重入时只刷新被标记失效的查询。本网页写操作会使缓存失效，但其他客户端、浏览器或 CLI 的修改不会通知已有网页，因此已访问的盒、文件夹和搜索结果可能持续显示旧数据。

新增两端共用的 `GET /api/v1/catalog-revision`，从现有日志边界派生不透明标记。客户端包含本机待提交日志的序号和校验，不以待上传数量或修改时间判断变化；检查不访问上游。接口禁止 HTTP 缓存，无数据库迁移。

应用级观察器在导航、重新聚焦、网络恢复和前台每 10 秒检查；只有标记变化才统一使查询失效。保留缓存中的数据、分页、筛选和滚动容器，活动页面原位重查，非活动列表进入时重查。首次检查避免已有缓存遗漏变化；检查失败不清空页面。保留原有客户端连接／同步状态提示。

## 验证

- 两端 API 测试：标记稳定、库写入改变标记、HTTP no-store。
- 库测试：其他主库句柄写入、同步下载、其他客户端句柄本地写入。
- 观察器测试：目录导航、相同标记不失效、变更覆盖文件／目录／搜索／组合／标签／盒／路径查询、保留数据、重新聚焦。
- 浏览器场景 `catalog-external-changes`：进入已有缓存的列表后出现外部新增文件，停留页面等待周期检查后显示外部改名；其余浏览器场景验证原有导航、分页返回和阅读器。
