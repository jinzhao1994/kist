# 目录与归档盒总大小

用户确认：在写入时维护当前文件的逻辑总大小，folder 覆盖子树，box 读取根目录统计；随版本更新自动迁移已有库。设计决定见权威设计 §1.7.3。

## 实现与升级边界

- 迁移 5 添加 `folders.total_size`、从 SQLite 元数据回填并安装触发器；DDL、回填、版本记录同事务。原文件与 ops 不变。
- 文件增删、换内容、换目录和目录移动同事务更新祖先；同内容多引用分别计入。blob 大小纠正覆盖已有引用。根目录为空时为 0。
- 统计不进入日志载荷或严格撤销的语义快照；查询模型才携带总大小。box 不增加重复列。
- Open 持库写锁迁移，独立 Goose provider 不使用进程全局配置；拒绝更新的 schema。旧程序已有 SQL 仍受触发器维护，但不承诺其 rebuild、快照或一般降级兼容；升级停止全部旧写入进程。
- snapshot/deep diff 包含大小列；deep verify 另行从文件与 blob 独立聚合检查。
- 目录列表、图标辅助信息、归档盒列表/卡片展示大小。目录大小排序仅在目录分组内生效，不改变文件分页顺序。

## 测量

命令：`go test ./internal/store -run '^$' -bench BenchmarkFolderSizeReads -benchtime=100ms`。

Apple M2、内存 SQLite、10,000 个文件共用 6 层目录、每份 1 KiB，2026-10-20 的一次实测：

| 操作 | 每次耗时 |
|---|---:|
| 现场聚合子树 | 3.51 ms |
| 读取物化总大小 | 3.80 µs |
| 替换文件引用，含祖先更新 | 90.0 µs |
| 同一替换，移除大小更新触发器作对照 | 8.97 µs |

查询收益以增加写入成本换取；此处单文件替换约增加 81 µs。不是 NAS、磁盘同步或整批导入端到端性能承诺。当前按文件更新祖先，未引入批次累加缓存；若真实导入成为瓶颈再测量合并策略。

## 验证覆盖

迁移旧库回填、失败回滚及重试、重复启动、未来 schema 拒绝；空目录、重复 blob 引用、文件换目录/换内容、目录跨盒及同盒移动、blob 元数据纠正、事务回滚、整数溢出拒绝；library 删除子树/撤销/重建/独立 deep verify、冻结旧日志回放及 API 返回。既有完整恢复、上传替换、快照及 catch-up 测试继续覆盖公共写入路径。

冻结 journal-v1 的 ops 原字节保持不变；预期快照的目录行只补充从原有 files/blobs 手工独立计算的 0、19、0、6、8 字节统计。

交付验证：`make check` 通过；本地已有预览库首次启动日志确认 schema 4 → 5，浏览器显示盒大小 675.5 kB、空目录 0 B。对升级后的同一预览库执行 `verify --deep`：no problems found，检查 12 blobs、1 box、33 条操作、16 个投影条目和 17 张重放表。正式视觉基准仍需按 CI 完整候选审阅流程处理，未用本地检查代替截图验收。
