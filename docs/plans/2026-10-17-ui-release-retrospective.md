## 哪些方法有效

- 在真实数据和实际浏览器里逐步收敛，比仅写组件或看合成截图更早暴露“难用”：搜索范围、同名标签、详情每次打开、输入框先删选中值等都属于行为问题。
- 保留小而可定位的中文提交，设计中记录被替代方案的原因，使回溯不依赖聊天记忆。共享控件、动作处理和域层函数减少了不同入口之间的差异。
- 后端不变量、独立 API/组件测试、真实媒体验收、视觉回归和发布产物测试各自检查不同问题。单个 `make check` 不能替代全部层级。
- 上传优化以阶段耗时与真实文件为证据：64 MiB 本机观察、WASM/CSP 回退诊断有用，但不是 NAS 性能承诺，也不能用失败的旧版计时计算加速比例。见[流式上传记录](2026-10-15-streaming-upload.md)。
- Docker Hub 是群晖实际使用反馈推动的分发补充；复用 GHCR 已验收 digest，避免两个仓库独立构建。停止 edge 消除了频繁 UI 提交引发的额外发布和队列干扰。

## 主要返工及改进

### 1. 局部“像”并不等于共用样式

标题行分别覆盖、链接手写成按钮、列表/网格额外 padding、上下两排图标不同间距，导致一个页面改好、旁边页面仍旧。`d517e84` 将标题规则提到共享 `.page-header`，`278e076` / `d48de89` 将下载改为 Mantine Button 并删掉旧 `.button-link`，才真正收敛。

**以后：** 先找样式拥有者、同类入口和既有组件；共享规则一次修改。迁移完成搜索旧引用，不留第二套近似样式。不为实现细节建立人工同步的数值表，实施规范链接源码。

### 2. 微调前没有先定信息层级

搜索条件从白缝到内描边、分段底色，再到整体浅底；标签从 X 到右键，再从 icon 到吊牌背景。它们最终解决的分别是“让值突出”“让整体有联系”“去掉低频操作占位”，不是某个边框必须多少像素。把“标签图案”误读成加 icon 也是没有区分形状与装饰。

**以后：** 把用户要解决的视觉关系先翻译成一句可检查的结果，再修改组件。已有授权的小改动直接做；只有不确定性会改变结果时才澄清。确认后覆盖 hover/focus/disabled，而非只调静态截图。尺寸问题读取边界和计算样式，考虑截图缩放。

### 3. UI 改了，测试与设计记录滞后

v0.1.4 发布前发现 14 个视觉场景采集失败：6 个详情状态和 3 个画廊行为仍期待详情默认展开；5 个历史场景缺少 `/ops/{id}/summary` fixture。修复后还同步了旧“文件名: 旅行”的定位器。主 `make check` 只编译/列举视觉用例并检查产物守卫，不执行截图，所以此前本地通过不能证明视觉已通过。

设计文档仍写“桌面默认展开”“悬停显示标签 X”，会让下一次开发重新实现已被放弃的行为。接受视觉基准过于频繁会增加排队，长期不修采集失败则会把问题集中到发版。

**以后：** 行为、默认状态、文案和请求变化同提交更新 fixture/断言；独立阶段处理真实采集失败。稳定设计后审阅完整差异并接受基准，不逐像素接受，也不放宽阈值、屏蔽请求错误或删除断言。设计文档就地修正当前结论，同时保留旧方案被替代的原因。

### 4. 焦点、偏好和异步生命周期也是 UI

刷新后“返回列表”橙色外框来自初始焦点；不稳定的 ref 还会重绑焦点陷阱。简单清除所有 outline 会破坏键盘操作。详情开关应区分首次默认值与保存偏好；弹窗异步挂载和立即卸载会跳过过渡。

**以后：** 使用共享 Dialog/Presence，稳定回调绑定；按初次打开、异步加载、Tab、关闭返回、刷新恢复分别验收。只有非操作性初始焦点容器隐藏 outline，操作控件保留可见焦点。存储失败不能使基本交互失效。

### 5. 发布候选没有一次收齐，重复跑了预演

此次先在 `380109b` 启动预演，之后又补视觉测试并更新基准，最终需在 `9afef41` 再预演。前一轮通过不能冒充最终提交证据。标签流水线再次检查是有意设计，不属于可随意删掉的重复。

**以后：** 先完成发布说明、测试、视觉采集/审阅/接受，固定最终 SHA；再运行一次针对最终候选的完整预演。记录 run ID 与 SHA，避免只看“最近一个绿色任务”。通用技能的四段版本号、PR、额外文件要求不适用于此仓库；以仓库发布流程为准，不为了工具重塑项目。

### 6. 发布完成、镜像可用、NAS 提示是三件事

本次正式 Release 从 12:26:31Z 到 12:33:15Z，约 6 分 44 秒；Docker Hub 最后的通道任务到 12:38:09Z 完成。也就是说标签发布流水线到全部分发结束约 11 分 38 秒，不含前置审阅和预演；这是单次观察，不是服务时限。

用户使用 Docker Hub `latest`，但群晖没有立即显示更新按钮。不能因此重发镜像、移动固定标签或声称发布失败；同样不能保证等 12 小时必然出现。先确认完整镜像名、标签、注册表端完成状态和实际运行版本，再检查 NAS 检测/网络。

**以后：** 分阶段报告状态和剩余检查，避免每分钟重复同一句等待；保持必要进度沟通，不把重复轮询当进展。升级指南区分兼容升级、破坏性迁移和旧版回退，不要求每次兼容升级做全量备份/scrub；保留正常备份安排。
