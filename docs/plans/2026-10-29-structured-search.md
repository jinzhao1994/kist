# 结构化字段搜索实验

本轮只验证投影与查询，不向正式资料库添加表或搜索 UI。权威值仍是 ops 中的 `facts:data`；候选索引由 `structured.Project` 单向生成。实验程序只创建临时 SQLite，退出删除，不访问任何真实资料库。

## 可复现方法

运行 `go run ./scripts/structured-search`。构造 10,000 份合成文件、70,000 个标量和 110,000 条所属对象关系。每份含两个不同人，甲的分数循环分布、乙固定高分；这故意制造文件级联接的假阳性。每条查询执行七次取中位数，并输出 `EXPLAIN QUERY PLAN`。实验数据、断言和程序均可公开。

2026-10-29 本机 SQLite 3.53.4 一次测量如下；这是暖缓存单进程实验，不是 NAS 延迟保证：

| 查询 | 命中 | 中位数 ms | 查询计划 |
| --- | ---: | ---: | --- |
| 号码，遍历 JSON | 1 | 152.519 | documents + json_tree 扫描 |
| 号码，标量索引 | 1 | 0.023 | exact_value 覆盖索引 |
| 姓名精确匹配 | 10,000 | 0.729 | exact_value 覆盖索引 |
| 名次 ≤ 10 | 1,000 | 0.092 | integer_value 范围索引 |
| 分数 ≥ 90 | 11,000 | 0.595 | real_value 范围索引 |
| 日期与六月相交 | 833 | 0.554 | date_range 下界索引，上界再过滤 |
| 同一人的姓名 + 高分 | 1,000 | 43.909 | exact_value + scope_identity + 主键 |
| 错误的仅按文件联接 | 10,000 | 15.862 | 同文件主键联接，产生 9,000 假阳性 |

构建约 2.4 秒；数据库约 30.3 MiB，包含 JSON 原文、投影、关联和全部候选索引，不能当作纯索引增量。实际部署还需测量冷缓存、并发、持久化写入和更大规模。

## 建议

- 不给整个 JSON 字符串建普通索引后期待内部字段变快；固定 JSON 路径的表达式索引也不适用于任意动态 key。采用固定列的标量表，固定数量的值索引服务所有 key。
- 同时保存精确路径、把数组身份替换为 `*` 的语义路径、叶子 key 和类型。路径用于选择具体角色，key 用于探索；只按 `name` 搜索可能匹配签署人，不等于“持有人姓名”。标签是显示文字，不能承担稳定索引身份。
- 号码始终是文本，保留前导零。整数单独用 INTEGER，不能先转 float64；实数用 REAL，要求精确十进制的未来财务需求另作设计。用时以秒投影，但保留 duration 类型，不能和分数混查。数值比较必须限定语义及单位；原型保留 unit，正式查询不能把不同单位直接比较。
- 日期投影为 `[下界, 上界)`，保持年、月、日的精度。UI 应明确“相交”还是“确定在范围内”，不能把只写年份的记录说成某日发生。区间索引只能有效缩小一侧范围，宽范围依然需要过滤。
- 重复对象保留所有数组祖先的身份和语义路径。组合谓词必须明确在哪层对象共同成立；例如同一个学生、或同一学生的同一次考试。不能只联接 file_id，也不能一概选择最近对象而丢掉嵌套关联。
- 删除子树及不确定值不进入确定事实索引；如以后支持搜索“待核对”，用显式模式而不是混入普通结果。人工修改在 JSON 中保留来源；索引更新从最终合并结果重算。
- 模型首轮命名仍有漂移：姓名可能位于持有人或比赛记录，地点/档案号也可能有不同 key。已有 outline 约束重提取，但不能保证跨文件的完全统一。正式搜索需要受控语义映射、字段探索与角色提示，不把动态标签无条件合并成一个固定字段。原始路径和关联必须保留，以便未来重建更好的映射。

正式接入时，用相同纯投影同时覆盖正常 apply、追赶、rebuild、snapshot 和 deep verify；索引不是第二份权威数据。本轮没有改变现有 `file_metadata.value` 的 TEXT affinity，也没有提前决定 B8 的全局数值迁移。
