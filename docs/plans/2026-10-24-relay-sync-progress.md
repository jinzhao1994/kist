# 多级离线同步实施记录

设计见 [多级离线同步](../design/2026-10-24-relay-sync.md)。本记录不能替代设计决定。

## 第一阶段：中继持久接收

已实现 library 层 ReceiveRelay / RelayStatus / StoreRelayOriginal：

- 原始 proposal 经过现有领域与原件校验，进入中继的 pending 日志；身份、时间、依赖和撤销引用不变。
- pending_custody 持久保存独立 RelayReceipt。它不会清空 pending，不会生成或占用主库 op ID。
- 原件先验证 hash、size，再放入受保护的 local-blobs；缓存逐出规则保持原有主库确认边界。
- 正式提交复用现有同步流程，结果查询区分尚待提交、提交结果不确定、冲突、放弃、替换及主库确认。
- 已发布的主库目录可恢复丢失的正式回执；同一 proposal 后续直连主库继续幂等。

测试覆盖：原件缺失与损坏、并发重试、enqueue 后未写 custody 的中断恢复、删除派生 DB 重建、丢失主库回复、直连主库去重、跨节点 LocalID 撤销、预检查冲突与主库提交拒绝、替换与放弃结果。

验证结果：针对性同步/缓存/中继 race 测试通过；完整 `make check` 通过（含 327 个前端测试、Go race 全套测试、架构检查与单二进制构建）。未修改 UI，因此本阶段没有视觉基准变更。按本次本地工作要求，未 push、未等待 GitHub CI。
