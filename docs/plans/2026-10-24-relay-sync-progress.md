# 多级离线同步实施记录

设计见 [多级离线同步](../design/2026-10-24-relay-sync.md)。本记录不能替代设计决定。

## 第一阶段：中继持久接收

已实现 library 层 ReceiveRelay / RelayStatus / StoreRelayOriginal：

- 原始 proposal 经过现有领域与原件校验，进入中继的 pending 日志；身份、时间、依赖和撤销引用不变。
- pending_custody 持久保存独立 RelayReceipt。它不会清空 pending，不会生成或占用主库 op ID。
- 原件先验证 hash、size，再放入受保护的 local-blobs；缓存逐出规则保持原有主库确认边界。
- 正式提交复用现有同步流程，结果查询区分尚待提交、提交结果不确定、冲突、放弃、替换及主库确认。
- 已发布的主库目录可恢复丢失的正式回执；同一 proposal 后续直连主库继续幂等。

测试覆盖：原件缺失与损坏、并发重试、enqueue 后未写 custody 的中断恢复、删除派生 DB 重建、丢失主库回复、直连主库去重、跨节点 LocalID 撤销、预检查冲突与主库提交拒绝、替换与放弃结果。

验证结果：针对性同步/缓存/中继 race 测试通过；完整 `make check` 通过（含 327 个前端测试、Go race 全套测试、架构检查与单二进制构建）。未修改 UI，因此本阶段没有视觉基准变更。按本次本地工作要求，未 push、未等待 GitHub CI。

## 第二阶段：双层交换与下游状态

已实现 library 层 RelayHead / RelayCatalog / RelayRootCatalog / ReceiveRelayPage / SynchronizeRelay：

- 主库目录与中继快照分别固定边界；按页保存游标，完整快照验证后才发布。
- 保留本机并行追加的意图，以独立上游标记防止重复转交、错误放弃或过早确认。
- 手机可取回笔记本未提交的修改、继续新增及撤销，再经笔记本提交到主库。
- 主库回执、冲突、放弃和替换结果通过快照向下传递；支持多层转交。
- 重试不增加无效日志；错误身份、主库边界、回执、依赖顺序与重复条目拒绝，不能污染可重建状态。

针对性 race 测试已通过：三实例文件上传和撤销、四实例多层转交、丢失中继回复、分页中断后删除 DB 重建、分页期间并行编辑、冲突与替换结果下传、确认后的主库直连去重、无变化轮询，以及错误快照拒绝。最终代码的完整 `make check` 已通过（327 个前端测试、Go race 全套、架构检查及单二进制构建）。本阶段未更改 UI 或启用运行中服务的新路由；未 push、未使用 GitHub CI。

## 第三阶段：网络、配置和完整链路

- 客户端提供独立访问凭据和带鉴权的中继接口，复用续传上传与原文件、预览按需缓存。
- 配置保存上游节点身份与祖先链；在线递归验证、请求经过链、防自连和防环。
- 同库切换验证既有正式历史；未确认分支或未完成传输禁止换节点，确认后通过可重放日志解除旧分支。
- 设置页复用原有凭据表格；同步侧栏、操作列表和本机历史区分保管与最终确认；不会把已交付操作重复计为待上传。
- 自动中继上传带快照条件，双向变化留给手动合并；状态和进度通过现有组件展示。

HTTP 三实例测试覆盖独立凭据、主库不可达期间继续提交、原文件上传读取、丢失保管回复后重试、最终确认、未确认分支拒绝换址、确认后直连、防自连/祖孙环/请求链环，以及撤销凭据。已有低层测试继续覆盖四层传递、撤销、冲突替换下传、分页中断和删除派生数据库后的重建。

本地预览链为 `19605 → 19604 → 19603`。19605 是新增的下游验收客户端，19604 的设置页可管理它的独立凭据。已在 Chrome 确认下游文件、图片/PDF/表格预览，以及设置与同步页面。正式 Linux 视觉基准仍须按项目流程在允许 GitHub 检查时采集，当前不更新基准。

最终 `make check` 已通过：330 个前端测试、API 契约与格式检查、视觉场景契约检查、Go race 全套、架构检查及单二进制构建。主库断连期间的三实例 HTTP 测试、丢回复重试、防环和最终交接均通过。新增中继视觉场景及请求 fixtures 已更新；本次只完成本地提交，不 push、不等待 GitHub CI。
