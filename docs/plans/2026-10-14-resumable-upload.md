# 可校验的断点续传

继承前一阶段 path / last_modified / size / sha256 清单、Worker 增量哈希、PutVerified、PrepareFiles 的最终 blob 复核及 ExecuteRequest。前阶段实现提交 8bf6d02；CI、Visual、Secret scan、两种架构容器检查和 Docker Hub 同步已通过；真实 Chrome 最大完整样本 1 GiB。32 GiB 和手机后台能力未验证，不据此承诺。

## 分阶段交付

1. 持久暂存内核：版本化清单、进度落盘、块校验、重复与偏移、锁、恢复、容量和过期取消；故障注入验证。
2. HTTP 与 library：会话接口、目标重新检查、最终整批校验、幂等完成和回执，保持普通上传兼容；接口与安全回归。
3. 浏览器：身份复核、分块、暂停/继续/取消、刷新重选恢复、错误与进度，保留旧服务器普通校验上传；自动测试。
4. 本机真实浏览器网络中断、刷新、重选、服务重启恢复验收；内容独立核对、make check、CI 与视觉审阅。

每阶段独立验证后中文提交并推送。只用本机开发资料库，不发布、不修改 NAS、不创建 PR。权威决策与取舍在设计文档，不在本计划另写一套协议。

## 暂存内核阶段

新增 `internal/upload`，只依赖 domain 与 lockfile；架构测试禁止它访问归档状态。版本化 JSON、编号暂存文件和固定 256 个锁槽均位于调用方指定的暂存根目录。尚未接入 HTTP/UI，当前普通上传行为不变。

确认顺序为数据写入、数据 fsync、进度临时文件 fsync、原子替换及目录同步。Windows 使用 write-through 替换，目录没有 POSIX fsync 接口；本阶段证明进程终止/重启恢复，不据此声称验证了 Windows 断电行为。创建在独立目录完成后发布；清理先改名为待删除目录，避免删除中断留下貌似正常的破损会话。

测试证据：

- 子进程分别在写完数据、数据同步、进度替换前、进度替换后直接退出；重新打开并验证可靠 offset、截断尾部、仅补传缺失后缀、最终字节一致。
- 创建进程在发布目录前退出，下一次创建清理遗留；清理在改名后中断，下次 sweep 完成回收。
- 重复块、偏移冲突、块摘要错误、整文件损坏、已确认文件截短、错误版本/JSON、符号链接拒绝。
- 部分写入后注入 ENOSPC、同步后取消、独立 Store 并发重传、并发创建总额度、8 会话数量上限、空文件、过期与续租、忙会话不清理、取消与完成终态。
- 本机 `go test -race ./internal/upload ./internal/arch` 与 Windows 测试交叉编译通过。完整交付检查记录于 `/tmp/kist-resumable-core-check.log`。

待后续阶段验证：HTTP 接收中断、library 目标复核与最终提交故障点、持久回执优先、浏览器刷新重选和服务重启，以及最终归档内容独立核对。

暂存内核提交 `68fffca` 的 CI（38502702278）与 Visual（38502702237）均通过，包括 Windows、macOS、ARM Linux 和 amd64/arm64 容器。Secret scan 通过。

## HTTP 与归档边界阶段

新增会话创建/查询/续租/分块/完成/取消接口及能力发现；原普通 multipart 路径保持。错误码区分可靠偏移、块摘要、会话版本/过期/损坏、配额和磁盘空间不足。OpenAPI 生成前端契约；浏览器尚未启用这些接口。

`library.UploadTarget` 在同一读取事务中签名 box 自身字段及目录祖先链，在 ExecuteRequest 持写锁时重新核对；新增 `CheckRequest` 只核对回执与输入，不产生 op。完整文件复核后继续调用已有 PrepareFiles/PutVerified/最终 blob 复核，再整批提交。回执优先于暂存状态与目标是否仍存在。

接口集成测试覆盖分块接收中断、错误长度/摘要和偏移、Host/Origin/跨站/媒体类型保护、服务重开后仅传后缀、下载原内容一致、重建与撤销后重试不复活、不同输入复用 key 拒绝、整文件损坏及未完成批次不归档、完成响应故障与并发重试只提交一次、取消不能撤销成功归档、过期会话可清理。在准备结束到提交之间注入 box 重命名/删除，均拒绝；无关目录新增不阻止提交。目录归属/删除与目标签名、零副作用回执查询另有 library 测试。

本机相关 race 测试通过；完整检查记录于 `/tmp/kist-resumable-api-check.log`。剩余浏览器状态恢复、真实浏览器断网/刷新/重选/后端重启及最终用户文档属于后续阶段，不以接口测试代替。

## 真实 Chrome 恢复验收

在本机测试库 `/private/tmp/kist-m6-browser.Iw2nEr`，Chrome 扩展连接上传合成的 256 MiB 文件 `resume-256MiB.bin`：

- 网络限速 4 MiB/s 后点击暂停，持久 state.json 确认 33554432 字节（32 MiB）；刷新后仍显示已确认 13%，并提示重新选择整个批次。
- 重选另一个目录下同名、同大小、同修改时间但不同内容的文件，界面明确拒绝，确认位置没有推进。
- 重选正确原文件，CDP 记录第一条 PUT offset=33554432，随后逐块递增。
- 模拟断网，页面提示中断且已确认 38%；磁盘记录 100663296 字节（96 MiB）。强制终止本机 serve 进程并重新启动同一个库，恢复网络后点击继续，第一条 PUT offset=100663296，没有从零上传。
- 最终页面显示文件已保存，列表由 3 个文件变为 4 个；会话完整位置 268435456，完成 op_id=30。独立 Python hashlib 对原文件、投影文件和最终 blob 分别计算，SHA-256 均为 `a628056e985233d39d0f47aeb5fd10d1c924620f0e84f7b8b47c8e74bdeb8ea4`。
- `kist verify --deep` 退出码 0：5 blobs、2 boxes、32 operations、8 projected entries、17 tables replayed，无问题。Chrome 的临时离线和限速设置已移除。

浏览器阶段 Visual 38506209641 中 75 项通过，两个新增用例因选择器同时命中文件输入框与可见按钮而失败；已限定实际 button。没有把失败捕获当作可接受基准。仍需复跑并审阅完整视觉产物。

本次真实续传样本为 256 MiB，不声明已验证 32 GiB、手机锁屏后台或物理断电。
