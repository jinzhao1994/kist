# M6 历史 UI

以设计 2.4、2.5、3.9 与第 7 节为准；GC 与保留期配置不进入 v0.1。

## 交付顺序

1. 操作历史 API：全库、box、文件、组与 action 筛选，按 op ID 分页，读取单条详情，复用持久请求去重与严格撤销。列表不读取 payload。
2. 历史查询：从权威日志全局前缀重放到独立临时 SQLite，再查询 box、文件、tag 与 metadata；读取历史原文件；支持历史状态对比。保留原时间，取消与失败时清理临时资源，不改变工作库或日志。测量重放成本后确定资源边界，不提前加缓存。
3. 中英文 UI：历史列表与详情、可定位的撤销冲突、只读历史 box、文件版本链对比、回收站与严格恢复。历史视图明确标识截止点，不混用当前标签名称或当前文件内容。
4. 验收：跨 box/global tag、导入与删除、撤销及撤销的撤销、metadata、历史只读、无效截止点、请求去重、rebuild 与 deep verify；真实浏览器流程及新增视觉基准。每阶段 make check、commit、push 并检查 Actions。

## 边界

- 撤销是一条新的补偿 op；恢复删除也使用原有原子撤销，不引入部分恢复或批量撤销。
- 文件版本链表示同一 file ID 经历的历史状态；当前没有替换文件内容的命令，不额外发明编辑/覆盖语义。
- 历史 API 为只读；原内容只按该时点 file → blob 关系解析，不允许任意 blob 路径访问。
- 不新增权威状态、不修改 op payload 协议、不让历史回溯触发 metadata 提取或派生媒体任务。

- 撤销复用持久请求去重，覆盖重复请求、重复撤销、阻挡操作编号、撤销的撤销和 rebuild 后重试。回执明确不可撤销。

### 第二阶段进行中：只读历史重放核心

- `ViewAt` 从全局日志前缀重放到库目录下独立的临时 SQLite；只暴露读取能力，查询结束、失败或取消时关闭数据库并清理临时目录。不同查询没有共享视图或缓存。
- 截止点须为当前已应用的操作，读取完该操作立即停止，不读取未来尾部；重放不持写锁，不调用提取器或投影。
- 对创建、修改、跨 box 标签、全局标签改名、metadata、删除及撤销的多个截止点，逐一对照当时保存的全表快照。验证历史原文件读取、已删文件拒绝读取、损坏前缀拒绝、未完成未来尾部隔离、查询生命周期独立、工作库和日志不变。
- 核心回归测试与 `make check` 通过；历史 HTTP API、比较与 UI 尚未完成。
- 性能样本：Apple M2 / macOS arm64，4,000 文件、502 op，`go test ./internal/library -run '^$' -bench BenchmarkHistoricalPrefix -benchtime=3x -count=1`，平均单次重放约 266 ms、累计分配 46.9 MB（不是常驻内存）。样本构建不计入重放耗时。当前无引入检查点的证据；API 阶段仍须约束并发和请求取消，不能将该样本外推为任意规模的固定延迟。

### 第二阶段：历史 HTTP API

- 提供 `/history/{op}/boxes/{id}`（按名称分页）、`/history/{op}/files/{id}` 与原内容接口 `?at={op}`。返回历史文件、目录、标签名称和 metadata，不混用当前实体；历史响应不提示当前版本的提取任务。
- 内容读取先解析该时点的文件关系，再打开原 blob。重放槽位在打开文件后释放，传输不占用重放容量；沿用当前下载安全头、HEAD 与 Range 路径。
- 服务实例最多两个并发重放，排队和执行共享 30 秒 deadline；超时为 503，不以当前状态代替历史。覆盖队列取消、失败释放槽位、历史分页、全局名称隔离、删除前原文件与删除后 404。
- `go test ./internal/api ./internal/arch` 和 `make check` 通过。版本比较 UI、回收站和浏览器验收仍待完成。
- `57ad949` 的 [CI](https://github.com/jinzhao1994/kist/actions/runs/38008775571) / [Visual](https://github.com/jinzhao1994/kist/actions/runs/38008775636)，以及 `b305727` 的 [CI](https://github.com/jinzhao1994/kist/actions/runs/38009160391) / [Visual](https://github.com/jinzhao1994/kist/actions/runs/38009160398) 均通过。

### 第三阶段：历史 UI 与回收站

- 增加中英文历史列表、box / 文件范围、操作详情、严格撤销确认和可点击的阻挡操作。操作目标由已有 handler 提取，列表仍不读取 payload；修正详情中未进入 OpenAPI 的匿名嵌入字段。
- 回收站从未被撤销的删除 op 查询，在分页之前过滤；包括文件、归档箱与标签，恢复以整条 op 为单位。覆盖恢复后消失、再次删除和 rebuild 后一致。
- 历史归档箱只读展示当时名称、日期、目录、文件与标签；版本对比显示两侧字段、metadata、标签路径及缺失状态，下载绑定历史截止点。文件不存在与截止点不存在分别处理。
- 新增前端回归测试：恢复响应丢失复用请求标识、冲突定位、删除前后比较、无效截止点与精确 metadata 文本。视觉测试新增历史、回收站、操作详情、历史归档箱、版本对比五个场景；基准审核仍待完成。

### 第四阶段进行中：严格撤销边界

- 回归测试复现导入之后的提取结果、空提取版本和用户 metadata 墓碑均会被旧撤销静默清除。新撤销在持锁追赶之后检查导入原始 metadata、captured_at 与提取版本，并定位相关文件的后续 metadata 操作，避免指向无关 box 改名。
- 保留旧 Apply 的日志含义；覆盖旧删除日志的追赶、rebuild、历史墓碑读取及 relink 后 deep verify。覆盖崩溃发生在 metadata 追加后的追赶校验、整批拒绝、拒绝不追加日志，以及先撤销 metadata 后正常撤销导入和恢复。
- 相关 library/API/架构测试与 `make check` 已通过；尚待远端验证，以及最终需求逐项核对和文档收口。
